## [Unreleased]

### Added
- **`movie_standardizer.py` places MP4 releases.** An `.mp4` download is now hardlinked into the library under its own extension — `Title (Year)/Title (Year).mp4` — instead of being left in the download folder as "not an MKV". Nothing is transcoded and nothing is renamed to a container it is not; the tool simply accepts a second container it can file honestly.
  - **MKV stays canonical.** When one movie arrives as both, the MKV is placed (it is the only container the rest of the pipeline can remux, inspect and subtitle), regardless of which file is bigger. When a library folder already holds one of the two, the other is declined and reported rather than added beside it: two features in one folder is exactly the layout `library_auditor.py` flags as `MULTIPLE_DIRECT_MOVIE_FILES`, and nothing here deletes the copy that is already there.
  - Replacement of a placed MP4 goes through the same ffprobe upgrade decision as an MKV — size alone still never replaces a movie.
  - Every other container (`.avi`, `.m4v`, `.mov`, `.ts`, disc images, …) is still declined, now with the reason "not an MKV or MP4; this tool never transcodes". The qBittorrent completion hook accepts an MP4 path on the same terms.
  - **What an MP4 in the library does not get**, stated plainly in `docs/tools.md` and the tool's own docstring: `library_auditor.py` reports it as `SINGLE_OTHER_CONTAINER`, and `mkv_track_cleaner.py`, `subtitle_fetcher.py` and `bitdepth.py` skip it. It plays; it is not maintained. A movie you want cleaned, subtitled and audited should still arrive as an MKV.
  - 13 new tests covering placement, the hardlink (`samefile`), idempotent re-ingest, the MKV-wins tie-break, both directions of the one-container-per-folder rule, the staged-remux false positive, and the unchanged declines. 1,870 → 1,883 tests.

### Changed
- **Every sweep now shows progress on a terminal, and nowhere else.** The track cleaner has always drawn a live line — one row per movie, rewritten as the remux advances. The other four tools went quiet: a 3,000-folder audit, an ffprobe pass over a library of 40 GB remuxes and an ffsubsync sweep that takes minutes per sidecar all printed a line *after* each item and nothing during it.
  - `organizekit/core/live.py` (100% covered) now owns the overwritable line: terminal width, left-truncation of long paths, the erase escape, the block glyphs and a naive "~4m30s left" estimate. `mkv_track_cleaner.py`'s `LiveConsole` keeps its own composition — no other tool has an hours-long child process to report percentages for — and loses its private copies of the primitives.
  - The auditor, the 10-bit inspector, the synchronizer and the standardizer each draw one progress line. It is erased before every permanent line: automatically by `RunLog` for the three tools that use it, and by a `logging.Filter` on the console handler for the standardizer, which logs through the stdlib.
  - **It is TTY-gated, and that is the point.** Off a terminal — redirected, piped, under `cron`, or with `--json` — every drawing method returns immediately, so log files, captured output and the JSON documents are byte-for-byte what they were. Tests assert that per tool, not just per class: each run is checked for the absence of a single carriage return or escape byte.
  - 39 tests, `organizekit/core/live.py` at 100%. 1,883 → 1,922 tests.
- **`subtitle_fetcher.py` is now completely covered: 94% → 100%.** The last ~200 uncovered lines were never one block — they were ones and twos across forty functions, and every one of them is a line that only runs on a bad day. A branch that executes only when something has already gone wrong is a branch nobody notices is broken, which is precisely the argument for testing it.
  - What is now pinned: the refusal arms of the pure helpers (timestamp padding, cue parsing, number coercion, the SubDL URL vetter); the malformed-document paths in the ASS/VTT converters; the three scrape adapters that had no suite of their own (Subf2m, Subsunacs, Subs.sab.bz) plus the search halves of SubSource and YIFY; the chain's download-leg breaker; the container-probe failures and the "mkvmerge answered something impossible" arms of the extraction path; the OpenSubtitles user-mode login and decompress failures; and the queue's download leg — a pick naming a provider this run has no client for, a scraped payload that outgrew the limit, a movie that changed mid-lookup, a sidecar that appeared from somewhere else.
  - **Seven lines are deliberately not covered, and say so in the source.** `# pragma: no cover` with a reason each: two `except ValueError` guards around `int()`/`float()` of a regex-guaranteed number, two `for…else` arms after loops whose last attempt always raises, and one `is None` check on a value the call site only sets together with its guard. They are defence in depth against a future edit, not reachable behaviour — an honest note beats an unexplained 99%.
  - **A gap nobody had noticed:** `tests/selftests` rebinds each tool's `run_self_tests` to the moved suite, so the `--self-test` body every tool actually *ships* — the field check an operator runs on the NAS, and the thing that answers "does this copy work on this machine?" — was run only by `organize.py test` in a subprocess, invisible to coverage. All six now also run from a clean import inside the unit suite.
  - +194 tests (two new files, `tests/test_fetcher_last_mile.py` and `tests/test_queue_last_mile.py`). 1,922 → 2,116 tests. No production behaviour changed: the only edits to `subtitle_fetcher.py` are the five pragma comments.
- **The fetcher asks both subtitle providers at the same time instead of one after the other.** Every movie that reaches the API tier with the title/year fallback enabled is offered to *both* providers — OpenSubtitles for an exact moviehash match, SubDL for a scored release-name match — and the better answer wins, so both lookups always happen. The second one merely waited for the first: two companies, two connections, two separate rate limits, one queue.
  - OpenSubtitles' search now runs on a single background worker while SubDL's runs on the main thread. Nothing that spends anything moved: SubDL's durable search reservation (persisted with `fsync` before every outbound attempt) is exactly why it is the one that stayed, and the ledger, every download and every state checkpoint are still written by one thread in library order.
  - The worker exists only when both providers are configured and the fallback is on; `--workers 1` disables it along with every other thread in the tool; a movie abandoned between dispatch and pooling waits for its lookup rather than letting it run into the next movie's turn.
  - **Measured, and smaller than it sounds** (`benchmarks/bench_provider_overlap.py`, two loopback servers and the real token buckets): with round trips well inside the 1.1 s per-host courtesy gap — a healthy provider — this is worth **nothing measurable**, because the gap is what the run is waiting on. It is worth **2×** once a provider takes longer than about half the gap to answer. It ships because it costs nothing, changes no verdict and no log line, and stops one slow provider from making the other one late.
  - Verified by running the same library at `--workers 1` and `--workers 8` and diffing every result row, every log line and the whole summary; by a barrier that only opens if the two lookups really are in flight together; and by 16 deliberate mutations, all killed. 1,845 → 1,870 tests.
- **The fetcher stops re-handshaking with servers it is already talking to.** Every provider call went through `urllib.request.urlopen`, which closes the socket after each response — so asking OpenSubtitles for a hash match, then SubDL for a release match, then a scraped site for a page, paid three TCP handshakes and three TLS handshakes for three hosts it will ask again a second later. The requests, their order and the per-host pacing are unchanged; only the sockets are.
  - `organizekit/core/nethttp.py` holds one idle connection per `(scheme, host)` and plugs in as a pair of `urllib` handlers, so no call site changed: `urlopen` is still `urlopen` and an HTTP error is still an `HTTPError` with a readable body.
  - A connection is reused only when it is provably clean — body read to the end, no `Connection: close` from the server, socket still there, idle for under 30 s. A bounded read that stopped early (the fetcher refuses oversized payloads without reading them) closes the connection instead, because the rest of that body is still on the wire.
  - A reused connection the server had already dropped is retried once on a fresh one. A *first* attempt is never retried, and neither is a timeout: both would report the real failure later and less honestly.
  - HTTPS keeps the verifying default context — certificates and hostnames checked — and a test asserts it, because a connection pool is exactly where a disabled check would go unnoticed.
  - Measured server-side by `benchmarks/bench_keepalive.py`: 200 requests to one host open **1 connection instead of 200**; 0.10 s → 0.04 s on loopback, and 24.3 s → 0.2 s once each new connection costs a realistic 120 ms of handshake. `ORGANIZE_NO_KEEPALIVE=1` restores the old behaviour.
  - 45 tests against a real loopback server (a mock cannot hang up on you), 100% coverage of the new module, 28 deliberate mutations killed.

### Fixed
- **A test that asserted a thread-scheduling accident.** `test_the_pool_never_works_more_than_one_chunk_ahead` compared the *order* in which four triage workers started their movies. That order is the OS's to choose: the test passed on Linux and failed on macOS, Windows and 3.13. It now compares the set — which is the actual invariant (the first two chunks, and nothing beyond).
- **Two resource leaks and a default that pointed at a drive nobody has.** Found by making the suite run on Windows, all three invisible on Linux.
  - `StateStore.__init__` connects, then reads the schema. Opening a file that is not a database succeeds and *reading* it fails, and the half-built store left its connection open. `open_state` turned that into a cache miss, as designed, while the handle stayed — and on Windows an open handle means nothing can delete or replace the file.
  - `default_reports_root()` returned the documented `E:\torrents\tools\ReportsAndLogs` on **every** Windows machine. Without that volume, every tool exited 2 while saving its own report. The documented location is still preferred when the drive is there; otherwise logs and reports go under `%LOCALAPPDATA%\organize`.
  - `organizekit/core/nethttp.py` now treats WinError 10053 as a dropped keep-alive socket. Linux reports a connection the peer closed as a reset or a remote disconnection; Windows raises `ConnectionAbortedError` instead, so the pool refused to retry the exact race it exists to handle. Still retried only on a connection this run reused.
- **The suite was green on Linux and red on Windows and macOS.** CI runs the whole suite on three operating systems and three Python versions; `main` was green everywhere, and the overhaul's new tests quietly assumed Linux. Fixed so far: a report assertion that read a path column the renderer elides (a macOS temp directory is 50 characters before the library begins), five `with sqlite3.connect(...)` blocks in tests that commit but never *close* — Windows will not delete a file another handle holds — and the standardizer's log handler left open across two live-console fixtures. Since then: every path assertion compares `as_posix()` or `str(Path(...))` rather than a hand-written `/`; the fake `mkvmerge` and `ffprobe` are installed as a `.bat` shim on Windows, because a shebang is not a thing there; the console-symbol subprocess is decoded as UTF-8 instead of the parent's code page; and the two tests for the mono wrapper, which is the non-Windows branch, are skipped on Windows.
- **`organizekit/core/nethttp.py` now treats WinError 10053 as a dropped keep-alive socket.** Linux reports a connection the peer closed as a reset or a remote disconnection; Windows raises `ConnectionAbortedError` instead. Without it the pool turned every Windows race into a failed request. Still retried only on a connection this run reused, never on a first attempt.
- **The held CI patch checked the wrong distribution name.** `docs/ci-workflow.patch` still read `importlib.metadata.version('organize')` after the distribution was renamed to `organizekit`, so the packaging job would have failed the moment the patch was applied. It also raises the coverage floor from 74% to 88%, comfortably under the measured 91%.

## [3.5.0] - 2026-09-06

**The overhaul release.** Six months of prose in one line: the repo went from
five standalone scripts with ~300 tests and no CI to a shared, packaged toolkit
with 1,800 offline tests, a SQLite state store, a JSONL run stream, an
`organize.pyz` zipapp and a tag-triggered PyPI release — measured at every step
in [`OVERHAUL.md`](OVERHAUL.md). Behaviour the tools already had is unchanged
except where an entry below says it was a bug.

### Changed
- **The fetcher's edges are covered, which finishes the test campaign on the largest file.** What was left uncovered was not provider work but everything around it: the configuration validator, the library walk, the layout contract, the ledger reader and the sidecar inspection each had branches no test had ever taken.
  - 66 tests: every refusal in `validate_compact_config` (each one is a line an operator has to act on, and they are all reported at once rather than one per attempt); the library walk skipping samples, non-MKVs, undersized files, symlinked files and folders, extras and disc trees, and a file that vanishes mid-walk; the one-movie-per-folder contract; the ledger read back from the log with a half-written event in the middle, a checkpoint for another library, a payload of the wrong shape, and a log that cannot be read at all (which stops the run rather than silently re-spending yesterday's allowance); sidecar inspection when the folder will not list, when the file will not read, when it is empty, over the size limit, symlinked, or named something else; the MKVToolNix lookup and the "never raises" external-command helper; and the subtitle-archive reader.
  - `run_external_command([])` raised `IndexError` instead of returning, which is the one thing that helper promises never to do. No caller passes an empty command; it returns `127` now.
  - Thirty-seven deliberate mutations, all killed. 1,734 → 1,800 tests; `subtitle_fetcher.py` 92% → **94%**, the repo 87%.
- **Fixed: a zip's hearing-impaired copy was only spotted half the time.** When SubDL ships several SRTs in one archive the tool prefers the plain subtitle over the SDH/HI one — but the pattern that recognises them contained `hi\\b`, an escaped backslash rather than a word boundary, so it could only ever match a literal `hi\b`. `SDH` and `hearing` were caught; the very common `...HI.srt` was not, and the HI copy won on filename order. The pattern now matches `HI` as a word (and still not the `Hi` in `High Fidelity`).
- **The SubDL client is tested either side of the search it already had tests for.** Its result parsing and scoring were covered; the request that carries it and the bytes that come back were not — which is the part that is metered, authenticated and turned straight into a file on disk.
  - 58 tests: the key travels in a header and never in a URL; a 429/5xx is retried but a 401 is not (asking again spends the quota twice); `Retry-After` is honoured, capped at 30 s, ignored when it is not a number, and applied to the whole host rather than the one request; a declared length over the limit is refused *before* the read and a body that lies about its length is still bounded; a non-JSON, non-object or error answer is quoted back rather than parsed. Then the download: a relative URL resolved against `dl.subdl.com`, an identifier turned into the documented v2 endpoint locally, a JSON redirect followed exactly once (and refused when it names another host), a zip picking the library release and skipping the HI copy, a gzip bomb stopped at the limit, and — for the file itself — no sidecar written for HTML, for an oversize payload, for a movie that changed during the lookup, or on top of a subtitle that appeared while the download was in flight.
  - Thirty deliberate mutations, all killed. 1,676 → 1,734 tests; `subtitle_fetcher.py` 91% → 92%.
  - One stale line removed: the zip reader re-raised its own verdict by matching two message prefixes, one of which no longer exists anywhere in the tool.
- **Fixed: Addic7ed rows were dropped when the row layout moved.** The adapter read a row's language as "everything before the word `Completed`", so a page that listed the download count before the completion status produced the language `English 1200 Downloads` and every English subtitle was skipped as non-English — silently, and indistinguishably from "the site has nothing for this movie". The language now comes from the language cell itself; the two completion checks below it are what refuses a draft, and both layouts (status in its own cell, status inside the language cell) are covered.
- **The seven scraped sites are tested as parsers, not just as a chain.** These are HTML pages built for humans and changed without notice, which is why every adapter parses defensively — but each one had only ever been run against a single good page.
  - 66 tests hand them a bad day: a transport answering 503 without raising, a DNS failure (named by host, never by query), a timeout and an over-size body; a Podnapisi payload that is not a list, entries that are not objects, a duplicate id, an unparseable year, a second page and nonsense pagination; an Addic7ed search page with 0 results but sidebar movie links, an 80% draft, a row with no download anchor and a hearing-impaired row; a SubSource URL guess that misses, a search hit for a different film and a slug page that 500s; a YIFY downvoted row, a row with no link and rows listed worst-first. The chain's own bookkeeping is pinned too: what counts as a hard failure, what counts as a parse failure, what a refused candidate must *not* cost a source, and every reason string the walk reports.
  - Thirty-one deliberate mutations, all killed. 1,610 → 1,676 tests; `subtitle_fetcher.py` 89% → 91%, the repo 87%.
- **Fixed: Subtitle Edit was never run through `mono`.** Its OCR backend resolves the program by looking at an explicit path, then `PATH`, then the known install locations — which include the Linux ones — so the `.exe` was always found there and the `mono` wrapper below that lookup was unreachable. A Linux install was therefore exec'd as a bare .NET binary. The wrapper is now applied after the program is found, and an install with no `mono` on `PATH` counts as a backend that is not installed (which the run explains) rather than one that fails minutes into a movie.
- **Fixed: `--ocr-args` accepted half a template.** The check passed if the template named `{input}` *or* `{output}`, while its own error message — and the tool's need to know where the OCR result landed — require both. A template missing either is now refused up front.
- **The extraction path is tested where it actually does the work.** Extraction is the cheapest way to cover a movie (no provider, no quota, no network), and after the queue work it was the largest uncovered area left.
  - 39 tests cover the USF converter (the rare XML subtitle format: conversion, empty cues, unreadable timings), the OCR backend lookup (a path handed in, a name on `PATH`, a known install location, a Windows `.exe` under mono, a custom command validated before it is trusted, and the notes each failure prints), `run_ocr` (output where it was asked for, output written beside the input and collected, output that cannot be collected, a failing backend quoted rather than raised, an empty result), and the inside of `_extract_one_track`: WebVTT/USF/SRT tracks, `mkvextract` exiting non-zero, `mkvextract` exiting *zero* and writing nothing, a track that converts to no cues, a sidecar that appears mid-extraction (create-only: the other file wins), a read-only folder, an OCR failure, an unreadable OCR result, and a backend that cannot read the codec.
  - Twelve deliberate mutations, all killed. 1,571 → 1,610 tests; `subtitle_fetcher.py` 86% → 89%, the repo 86%.

- **Fixed: the ledger forgot how a download ended.** The run's durable ledger is append-only and each checkpoint carries only the records that changed since the last one. A movie that gets as far as a download is checkpointed twice — once to reserve the provider request *before* it is spent, once for the outcome — but the first checkpoint clears the changed-record set and recording an outcome did not put the record back into it. Every outcome after a reservation was therefore dropped, leaving the ledger claiming a download was still reserved for a movie that had actually been downloaded, was already covered, or had failed. The scraping branch already re-marked its record for this exact reason; the download branch now does too. Found by the new tests below.
- **The queue's failure branches are tested end to end.** `queue_run` is mostly not the happy path — it is the twenty-odd places where something goes wrong for *one* movie and the run has to record that movie's status and carry on, which is the property that makes a nightly job over 900 movies usable at all.
  - 18 tests cover a movie that cannot be hashed, a movie that changes while it is being hashed, a movie that vanishes between the scan and the read, an OpenSubtitles title search that goes down (once with SubDL to fall back to, once without), a SubDL title search that fails, a crash inside a scraped adapter, bytes an adapter should have rejected, a subtitle that appears from elsewhere mid-download, and the two ways the run can be told to be stricter (`--no-identity-fallback`, and a filename with no `Title (Year)` in it). Every one checks both what happened to that movie *and* that the next movie still got its subtitle.
  - A nineteenth test runs a whole dry run through the extraction path, which had only been exercised one function at a time.
  - Eleven deliberate mutations of the queue's failure handling, all killed. 1,552 → 1,571 tests; `subtitle_fetcher.py` 84% → 86%.

- **The replacement fetch is tested end to end.** `refetch_english_srt` is the seam between the two tools — `sync_subtitles.py` calls it when ffsubsync cannot trust the sidecar it was handed — and it is the only code here allowed to overwrite a subtitle a user already has. It was also the largest uncovered block in the largest file, because reaching it needs a library *and* a provider.
  - 27 tests run the real function against the fake providers installed at `urlopen`, and each one ends by asking what is in the movie folder now. **The caller's sidecar survives everything that can go wrong**: no API key, no qualifying candidate, every candidate already tried, a search outage, a download outage, an HTML error page served as a subtitle, the movie changing mid-fetch, and a failure of the rename itself. It is replaced only by bytes that arrived complete and validated, in a single atomic swap, with no temporary file left behind either way; a symlink sidecar is never followed; and machine-translated, non-English and wrong-movie uploads are still refused.
  - Ten deliberate mutations of the function, all killed. Two of them — the re-validation of the staged bytes and the publish step — are unreachable failures from outside and are pinned by fault injection, because they are the last two things standing between a provider hiccup and a movie whose subtitle is now an error page.
  - One flake worth recording: the concurrent-change test passed on its own and failed in the full suite, because a same-size in-place edit inside a single filesystem timestamp tick is invisible to a (device, inode, size, mtime) snapshot. The test now changes the size, and says why.
  - 1,525 → 1,552 tests; `subtitle_fetcher.py` 82% → 84% and the repo 84% → 85%.

- **The fetcher's planners are now checked against inputs nobody wrote.** The property harness added earlier covered the HDR rule, the remux plan, the subtitle contract and the naming handshake — but not `subtitle_fetcher.py`, which is the only tool here that acts on input from strangers. Its selection planners are pure functions of what a provider said and its quota arithmetic is a promise to that provider, which is exactly the shape a table of examples covers worst.
  - **Twenty properties**, each holding for every generated answer list: the chosen subtitle is always one that was offered; a machine-translated, AI-translated, foreign-parts-only or non-English entry is never chosen by any of the three selection routes; the hash route only installs a hash match whose release names the movie; the order the provider listed its answers in cannot change the pick; offering an entry the policy refuses changes nothing; an unbroken tie is held for review rather than guessed; a SubDL release match is never below the documented 0.80; pooling two providers never invents a third answer and never picks the worse-ranked of the two; a scraped shortlist is a subset that names the movie and respects its own limit; a download URL is `https://dl.subdl.com/subtitle/…` or it is refused; a daily cap is never exceeded however many movies ask; the two SubDL allowances are metered apart; and a download reserved today is never reserved again today.
  - **The generator had to be taught to produce hard cases.** Purely random candidates almost never produced an *acceptable* one, so the properties were passing by refusing everything; weighting the strategy towards the movie being asked about took the accept rate from 0.1% to 16–43% per route. A mutation sweep then showed two properties still green with the code broken — resolving a tie by guessing, and dropping the sort's tiebreakers — because random candidates never collide on a rank key, so the list strategy now sometimes clones a candidate, the way a real provider does.
  - 24 more tests, 1,501 → 1,525. **Twelve deliberate planner mutations, all killed by the property file on its own**; four are kept as `MutationTests`. One of those caught the oracle bug the harness exists to catch: the download-URL property was reading the expected host out of the module it was judging, so pointing that constant at `evil.example` left it passing. It spells the host out now.

- **The probe caches now live in the same database as everything else a run remembers.** `state.db` held verdicts, quotas and events, while the expensive thing a maintenance pass actually reuses — the `mkvmerge -J` and `ffprobe` output for files that have not changed — sat in two ad-hoc JSON caches with two different layouts, one per tool, rewritten whole on every run. They are now rows in a `probe` table keyed by `(path_key, tool)`.
  - **The rule that makes this safe is unchanged**: a payload is reused only while the file's size *and* `st_mtime_ns` are both unchanged, and only the probe *output* is ever stored — never a tool's verdict. Every decision is still re-derived from live filesystem state, so a cached entry cannot make a run blind to a sidecar that appeared, a hardlink count that dropped, or a remux that landed.
  - **No warm cache is lost and no scheduler line breaks.** `--cache` still takes a path, and a `.json` one keeps the old per-tool file format exactly as before. Without one, payloads follow the run's state cache — and a JSON cache left by an earlier version is imported once, the first time the database is found empty. The old file is left where it is; it is derived data, and deleting it is not this code's decision.
  - **One file means one switch**: `--no-state` and `ORGANIZE_NO_STATE` turn the probe cache off along with the rest of the state cache, because it *is* the rest of the state cache. `--no-cache` still skips probe reuse on its own. Reading never creates the database, so a run that learns nothing leaves the disk as it found it, and every storage failure — missing, corrupt, foreign, a directory in the way, a row whose payload is not JSON — is a cache miss rather than an error.
  - 38 more tests, 1,463 → 1,501; `organizekit/core/probecache.py` **94%** covered, toolkit **84%**. Checked against twelve deliberate mutations, all killed — including reading another tool's payloads, ignoring the mtime stamp, re-importing the old JSON over newer rows, and letting an eviction survive in the table.

- **The fetcher's other two subtitle tiers are now run end to end as well.** Phase 6o drove the run loop against OpenSubtitles; SubDL and the seven keyless scraped sites behind it were still only unit tested, so the rules that matter most — how the three tiers are *pooled*, what each one costs, and what happens when one is out — had never been executed by a test.
  - **`tests/fake_provider.py`** now also answers SubDL's two v2 routes per movie (the release-aware `/files/search` and the weaker title route) and, through `FakeSites`, the scraped tier's HTML pages; a router puts every source behind one `urlopen`, which is the only way to test sources the tool documents as equals.
  - **Equal sources means the provider is not the tiebreak.** The most-downloaded qualifying release wins whoever has it: a 400-download SubDL match beats a 10-download OpenSubtitles hash match, and a 9,000-download hash match beats the same SubDL entry. When one provider's daily cap is spent the run simply covers the next movie from the other.
  - **SubDL's claims are checked before its bytes are.** A `match_score` below 0.80 is not treated as a release match, subtitles filed under a different movie are refused, and non-English or explicitly non-SRT entries never reach a download. Its search and download allowances are metered separately and both survive into the next run — and an exhausted download cap defers the next movie *before* the lookup, because a search whose result cannot be used is a wasted request.
  - **The scraped tier is a failover chain.** It stops at the first site that answers (one site contacted, six left alone); when no site has the movie all seven are asked once each, and every search is reserved in the durable ledger under its own field. `--skip-source` is honoured, `--scrape-daily-cap 0` turns the tier off, a dry run asks nothing at all, and a site that fails three times in a row is dropped for the rest of the run.
  - 25 more tests, 1,438 → 1,463; `subtitle_fetcher.py` coverage 80% → **82%**, toolkit **84%**. Checked against twelve deliberate mutations: eleven killed outright, and the twelfth — deleting SubDL's English-language gate — survived only because a second gate downstream refuses the same entry; removing both at once is killed.

- **The fetcher's run loop is now exercised against a provider that answers.** `subtitle_fetcher.py` is the largest tool here and the only one that reaches the internet. Its planners are tested as pure functions and its clients against canned payloads, but `queue_run` — the 650-line orchestrator that ties triage, quotas, provider calls, validation and the report together — was barely covered, because reaching it needs a library *and* a provider.
  - **`tests/fake_provider.py`** supplies the provider one layer below the client, at `urllib.request.urlopen`: the real client builds the real request and the real run decides what to do with the answer. 39 tests then pin the behaviour an operator depends on — a hash match is downloaded, validated and written as `<movie>.eng.srt`; a covered movie costs no request on the next run; a legacy `.en.srt` is promoted rather than re-downloaded.
  - **Every refusal is checked through the whole program, not at the decision function.** A release with no Blu-ray keyword, a machine-translated entry and a non-English entry are all declined without spending a request. Bytes that are not an SRT are rejected *after* the download — and the reservation they spent is still recorded, because the provider counted it. A plain-HTTP download link is refused. A movie rewritten while its subtitle is in flight does not get that subtitle: the file was chosen for the bytes that were there when the lookup started.

- **Thirty-eight invariants, checked against inputs nobody thought of.** The suite was strong on examples — a table somebody wrote out, a fault injected at each step of a transaction — and had none of the other kind of test: state a rule, then let the machine hunt for a counterexample. `tests/property.py` is that harness in sixty lines of standard library (`hypothesis` is not available to an offline, zero-dependency repo), and `tests/test_properties.py` aims it at the four places an unforeseen input would be expensive to get wrong:
  - **The fail-closed HDR rule.** Queueing a Dolby Vision master for re-encoding is the most destructive thing this toolkit could do, and the rule is "when in doubt, never queue". The properties generate ffprobe payloads out of real pix_fmts, transfer functions, DOVI/HDR10+/mastering-display side data and `HDR_Format` tags, and assert that an HDR file is never queued, that *adding* any HDR marker to any file can never make it queueable, that an unknown bit depth is always reviewed, that the verdict does not depend on the order ffprobe listed things, and that cover art is never mistaken for the feature.

Version 1.3.1.
- **`organize.py doctor`'s OCR check now surfaces *why* `subtitle_fetcher` could not be imported or no backend was found**, instead of a generic "not found" message with the exception swallowed.
- **`jellyfin_one_shot.py` dry-run and empty-library infinite loops** (see Added above): a `--dry-run` without `--max-passes` previously looped forever because nothing it does can move the auditor's verdict, and an empty (or wrong) `--source` looped on 0/0 coverage.
- **`jellyfin_one_shot.py` hot loop when the audit keeps failing** — a broken or lock-blocked auditor left the runner on "unknown" coverage with no backoff; per-pass audit retries (5/15/45 s) plus a three-pass hard stop make the failure mode visible and bounded.
- **`sync_subtitles.py` remembers what it already measured, so a re-run costs nothing.** Measuring a movie means a full ffsubsync run — an audio decode and an alignment pass — and the answer cannot change while the two files are unchanged. A sidecar that measured "in sync", or was corrected and swapped in, is now recorded outside the library (`ReportsAndLogs/sync_subtitles/sync_state.json`, override with `--sync-ledger` or `SUBTITLE_SYNC_LEDGER`) with the subtitle's SHA-256 and the movie's size and mtime. The record is treated as evidence, never as a decision: it is honoured only while **both** the sidecar bytes and the movie bytes still match it, so a re-downloaded, re-extracted, hand-edited or replaced subtitle, or a remuxed or replaced movie, sends the sidecar straight back through ffsubsync. Held-for-review and failed syncs are never recorded — those still need another attempt. The report gained a "Remembered in sync" scorecard row and a "REMEMBERED IN SYNC (NOT RE-MEASURED)" section, the log gained the same count, a dry run reads the memory to show what a live run would skip and never writes to it, and the ledger is rejected inside the library exactly like `--log` and `--report`. Deleting the file re-measures everything. `jellyfin_one_shot.py` pins it under `--log-dir` (`--sync-ledger <log-dir>/sync_state.json`) like every other artifact of a run. Version 1.1.0.
- **`jellyfin_one_shot.py` audits before it works, so a finished library is left alone.** The orchestrator used to run all five tools and only then ask the auditor whether the library was complete — so re-running a library that finished yesterday cost a full sweep for nothing. A live run now audits first (the auditor is filesystem-only: it reads folder layout and the sidecar, never the container) and, when the verdict is already 100%, exits 0 with a banner naming what the verdict does and does not cover. `--force-pass` restores the old behaviour for a real sweep — which is the right thing when movies still carry extra audio tracks or embedded subtitles, because the auditor's contract deliberately does not inspect the MKV's own tracks. A pre-flight audit that is blocked or broken is not a verdict: the run falls through to the normal pass loop with its retries and bad-audit accounting intact, and an empty library is still caught (exit 2) before any sweep. `--dry-run` is unchanged and always previews exactly one pass. Version 1.2.0.
- **`mkv_track_cleaner.py` no longer re-scans every movie on the run right after it cleaned them.** The probe cache stores `mkvmerge -J` output keyed on `(size, mtime)`, but the entry was written from the *pre-remux* stat, while a remux deliberately restores the source mtime and changes the size. That entry could therefore never match the file it described, so the next run re-ran a full container scan of every movie the previous run had just cleaned — the whole cost of a "nothing left to do" maintenance pass, for a library that had not changed. The cache is now re-keyed onto the file that actually exists, using the verification probe of the finished output (the same bytes `mkvmerge -J` would return). Measured on a simulated 10-movie library: the pass after the remux went from 10 container scans to 0, and it stays at 0 on later passes. Version 2.6.1.

## [3.3.0] - 2026-08-30

### Changed
- **The repo is now as simple as the tools are standalone.** The shared module `common.py` is gone: every helper it provided (report rendering, fail-closed locks, the SRT sidecar contract, probe cache, atomic writes) is now **vendored inline** in a clearly marked section at the top of each script that uses it. Each of the five tools is a single self-contained file — copy just the one(s) you need into your own setup and run them with nothing but Python 3.11+ and the standard library. `organize.py` (unified CLI / doctor) and `pipeline.py` (ordered sweep) remain as the convenience layer on top.
- `tests/test_common.py` was dissolved: its suites now live next to the code they exercise (`test_10bit.py`, `test_movie_standardizer.py`, `test_subtitle_fetcher.py`, `test_reports.py`), including a rewritten "no tool keeps a divergent copy of the subtitle contract" suite that compares the vendored copies against each other.
- README rewritten as a single document: what the toolkit does, the file map, per-tool quickstarts, and how to adopt just one tool.

### Removed
- Docker support (`Dockerfile`, `docker-compose.yml`, `.dockerignore`) — the toolkit never needed a container to begin with.
- Windows launcher scripts (`organize.bat`, `organize.ps1`) and shell wrappers (`organize.sh`, `run_tests.sh`) — `python organize.py ...` is the one documented way to run everything.
- The `docs/` folder (architecture, configuration, FAQ, Docker and OS-specific guides) — the README is now the only documentation.
- `requirements.txt` / `requirements-dev.txt` — there are no runtime dependencies; `pytest` moved to the `dev` extra in `pyproject.toml`.

### Compatibility note
- If you import `common` directly from an external script, update it to import the helpers from a tool instead (e.g. `from library_auditor import Report`); every tool exports the shared helpers it vendors. All documented CLI behaviour is unchanged.

## [3.2.0]

### Changed
- **Every report now shares one layout.** A new renderer in `common.py` (`Report`, `report_banner`, `print_text`) draws all six reports — `subtitle_fetcher.py`, `library_auditor.py`, `mkv_track_cleaner.py`, `movie_standardizer.py`, `10bit.py` and the `pipeline.py` summary — with the same boxed header, the same right-aligned scorecard, and the same titled sections. Each report leads with the counts, then a one-line "Start here:", then the groups ordered by how cheap the fix is, then the full inventory. Nothing overflows the page and no line carries trailing whitespace.
- **`subtitle_fetcher.py`'s report answers the two questions you actually ask.** Movies are no longer dumped into one flat list tagged with a status word: every result now carries a machine-readable reason, so the report splits cleanly into **MOVIES THAT NEED A SUBTITLE** (grouped by the fix — unusable sidecar, misnamed sidecar, layout defect, held for review, no provider match, deferred by quota, error) and **MOVIES THAT ALREADY HAVE AN EXTERNAL `.eng.srt`** (every covered movie listed with its sidecar file name). Movies the UTC cap cut off before they were scanned are now *named* in the report instead of only counted.
- **`library_auditor.py` leads with defects.** "Folders that need attention" now comes first, grouped by fix, with the full folder-by-folder inventory and the file-type table moved behind it.
- **`10bit.py` leads with the queue.** The HandBrake queue and the two REVIEW groups come first; native-HDR and already-high-bit-depth movies are listed last, as confirmation that nothing should be touched.
- **`mkv_track_cleaner.py` leads with what needs a decision** — errors, movies remuxed without a validated `.eng.srt` (moviehash now invalidated), hardlink-deferred movies and layout skips — before the per-movie remux detail.
- **`movie_standardizer.py` leads with `ITEMS LEFT IN SOURCE`**, the only section where inaction silently leaves files in the torrent folder forever.
- **Tool output no longer clutters the torrents root on Windows**: logs, reports, and probe-cache JSON now default to `E:\torrents\tools\ReportsAndLogs\<tool>\` (e.g. `E:\torrents\tools\ReportsAndLogs\mkv_track_cleaner\mkv_track_cleaner.log`) instead of five folders at the root of `E:\torrents`. Existing hooks scheduled with direct tool paths pick this up automatically; anything using explicit `--log`/`--report`/`--cache` paths is unaffected.
- **Foreign films with a validated `.eng.srt` are now cleaned** by `mkv_track_cleaner.py`: the best non-commentary audio of any language is kept, commentary/DVS is dropped, and every embedded subtitle is stripped so the external SRT is the sole subtitle option. Foreign films *without* a validated sidecar remain untouched.
- **Canonical external subtitle suffix is now `.eng.srt`** (ISO 639-2/B) instead of `.en.srt`.
  `subtitle_fetcher.py` writes `.eng.srt`, `mkv_track_cleaner.py` requires it before stripping embeds,
  `library_auditor.py` and `movie_standardizer.py` treat it as the sole canonical sidecar name.
  A validated legacy `.en.srt` is automatically renamed to `.eng.srt` on the next fetcher, cleaner, or auditor run.

### Fixed
- **`movie_standardizer.py --help` reported a stale default report path.** The `--report` help string claimed an old default of `E:\torrents\movie_standardizer\movie_standardizer_report.txt`, but the actual default (and the report that is written) is `E:\torrents\tools\ReportsAndLogs\movie_standardizer\movie_standardizer_report.txt`. The help now matches the real constant, consistent with every other tool's `ReportsAndLogs` default.
- **`mkv_track_cleaner.py --version` printed the old script name.** It hardcoded `track_cleaner.py {VERSION}`; every other tool derives its name from the invoked path (`%(prog)s`). It now prints `mkv_track_cleaner.py {VERSION}`.
- **Placeholder-free `f`-strings and an unused `except` binding were removed** (`organize.py`, `library_auditor.py`) — caught by the project's `ruff` rules.
- **Reports no longer depend on the console's encoding.** Every tool now pins its own stdout/stderr to UTF-8 with `errors="replace"` on *every* platform (`common.enable_utf8_stdio`; previously this ran on Windows only), the `log()` helpers print through the encoding-safe path, and every caller that captures a child process — `organize.py` and the test suite — decodes it as UTF-8 instead of with the locale encoding. Before this, a boxed report was a `UnicodeDecodeError` waiting to happen on Windows (cp1252) and a `UnicodeEncodeError` on a runner with no locale set. The report *file* is written UTF-8 either way, so a limited console degrades to `?` instead of losing data or aborting a run.
- **Report entries wrap instead of being cut off.** `Report.entry()` used to ellipsize an
  entry that overflowed the 96-column page, which silently destroyed exactly what the line
  was there to name: on macOS the standardizer's source paths run ~90 columns, so
  `.../final/Small.1995.mkv` printed as `.../final/Small...`. Entry text now wraps at path
  separators (`common.wrap_path_text`), so the movie folder or file name always lands whole
  on its own line; the boxed header's metadata rows break the same way instead of splitting a
  directory name mid-word. A detail that shares an entry's line now really does start at its
  column instead of drifting four columns right. Tables still clip — columns have to line up.

### Added
- **SubDL is now a first-class subtitle provider.** Configure `SUBDL_API_KEY` to add SubDL's documented release-aware `/api/v2/files/search` fallback after OpenSubtitles has no safe exact-hash or title/year candidate, or run SubDL by itself when OpenSubtitles is unavailable. Automatic release picks require the response `match` to confirm the canonical movie and `match_score >= 0.80`; strict title/year lookup occurs only when the filename route yields no usable candidate, never after a low-score or ambiguous one. The v2 client uses Bearer authentication, sends only the local basename, requests the documented `format=file` opaque-ID download route, validates raw download hosts, fails closed on multi-SRT archives, rechecks the movie snapshot, and never logs provider URLs or credentials. The append-only ledger separately reserves OpenSubtitles downloads plus SubDL's documented free-tier 2,000 searches and 50 downloads per day; each SubDL search request (including a retry) and selected download is reserved before it is sent.
- **Expanded provider coverage tests** exercise SubDL v2 authentication and documented response parsing, match-record identity validation, score gating, safe URL handling, multi-file archive rejection, SubDL-only operation, release-to-title fallback ordering, and separate search/download quota reservations.
- **28 new report tests** (244 total): `tests/reporttext.py` parses the scorecard and sections back out of a rendered report, `tests/test_reports.py` builds one report per tool and asserts the shared contract, and `tests/test_common.py` covers the renderer itself (width invariants, wrapping, clipping, partial-run tallies), and `tests/test_reports.py` runs the fetcher under `PYTHONIOENCODING=ascii` to prove a hostile console cannot abort a run or corrupt the report file.
