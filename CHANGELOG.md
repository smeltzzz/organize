## [Unreleased]

### Added
- **The two decisions that spend your provider quota are now functions you can read.** `subtitle_fetcher.py`'s `queue_run` is a 700-line loop, and buried in it were the rules that decide, before a single request leaves the process, whether a movie costs anything today: what its own durable ledger record already proved (`plan_from_history`) and which sources still have local capacity (`plan_sources`). Both are now module-level pure functions returning small frozen dataclasses, with the retry economy stated in one place — a movie the scraping tier exhausted *today* is not offered to it twice; one that exhausted it on an earlier day goes straight back to scraping because the API tiers are already known to miss for it; a manual-review hold is honoured until a genuinely new source appears; a download reserved today waits for the next UTC day rather than being reserved twice. Behaviour is unchanged and the existing end-to-end queue tests prove it; what changed is that these rules can now be tested as a table instead of by running the whole fetcher against live providers.
- **The OpenSubtitles transport and its download safety rules have direct tests** (`tests/test_opensubtitles_client.py`, 29 tests against a fake `urlopen`): the finite retry ladder, a 404 that is never retried, a `Retry-After` that penalises the *host bucket* rather than the request (capped at 30 s, nonsense values ignored), the one-shot token refresh that cannot become a login loop, and — the part that matters — every check between "the provider handed us a link" and "there is a subtitle beside your movie": a non-HTTPS or schemeless link is never dereferenced, an oversize payload is refused whether or not it was declared, an HTML error page is not a subtitle, a movie that changed mid-lookup gets no sidecar, and a sidecar that appeared meanwhile is preserved rather than overwritten.
- 66 more tests, 779 → 845. Coverage 75% → **76%**; `subtitle_fetcher.py` 74% → 77%.
- **The promise that a power cut cannot cost you a movie is now executed, not argued.** `tests/test_crash_safety.py` injects a fault at each step of the remux transaction — after the journal is written, after mkvmerge finishes, after verification, between the staging file and `os.replace`, inside `os.fsync` — and then asks the filesystem the only two questions that matter: is anything lost or half-written right now, and does the next run clean it up? The crash is raised as a `BaseException`, deliberately not an `Exception`, because every tool wraps its work in `except Exception` to turn a bad movie into a reported error: an ordinary exception would have tested the tidy-up path and never the state a real crash leaves behind.
  - Recovery is held to the rule the code already claimed: an intact original means the staging file is discarded, not promoted; a verified temp whose bytes changed afterwards is kept for review; an unverified temp is never swapped in on the strength of being a readable MKV; a staging file younger than a minute belongs to a run that may still be alive. A hand-planted journal naming `../precious.mkv`, an absolute path, or a mismatched token is refused before anything is touched.
  - The staging file that `sync_subtitles.py` strands when it is killed mid-swap is asserted to be invisible to every other tool — not discovered as a subtitle, not counted by the auditor — so debris cannot become a wrong answer later.
- **The track cleaner is now tested end to end against a fake mkvmerge that is a real program.** `tests/fake_mkvmerge.py` speaks the subset of the mkvmerge command line the cleaner actually sends (`--version`, `-J`, `-o` with `--audio-tracks`/`--subtitle-tracks`/`--no-subtitles`/flag options, `--gui-mode` progress) and is launched as an actual child process, so `tests/test_track_cleaner_e2e.py` exercises the real argument parsing, directory scan, coordination and single-instance locks, `subprocess.Popen` plumbing, progress parsing, transaction journal, verification, `os.replace`, metadata cache, report and exit codes. A "movie" carries its own track list in its first line, so a remux really does produce a cleaner file and the second run really does find nothing to do.
- **`tests/test_standardizer_destructive.py` covers the only tool that deletes folders**, in all three maintenance modes: what it removes (a provably smaller duplicate, an empty shell, a sample video, an extras folder with no movie in it) and, more importantly, what it refuses to remove (a near-identical size, a video-less folder that still holds a subtitle, a Jellyfin multi-version set, an extras folder that turns out to contain the feature, anything at all under `REPORT` or a dry run).
- 82 new tests, 697 → 779, still fully offline and under 10 seconds. Coverage 69% → **75%**: `mkv_track_cleaner.py` 47% → 75% (it was the worst-covered file and it is the one that rewrites and deletes movies), `movie_standardizer.py` 56% → 67%. The CI floor moves 65 → 72.
- **Rate limits are now per host, which cuts 30 minutes of pure sleeping to 9.5 on a 200-movie scraping pass.** The subtitle fetcher's scraping tier drives seven different sites through one transport object, and that object held a single "last request" timestamp: a request to Subf2m waited a full second because the previous request went to Podnapisi. Nobody was protected by that wait — they are seven servers with seven separate limits. Each host now has its own token bucket (`organizekit/core/ratelimit.py`), and every site is still paced to exactly one request per second; the win is only the waiting nobody was owed. The same applies inside the API clients, whose API host and download host were also sharing one budget. Measured with `benchmarks/bench_scrape_gaps.py`: 1,800 s of throttling → 571 s over 1,800 requests, **3.2×**, with the busiest single host still paced to its full 257 s of gaps (the script asserts that floor before printing).
  - **A `Retry-After` now holds the host back, not the request.** A 429 is information about the server, so the penalty goes into that host's bucket and every later caller waits it out once, instead of one unlucky request sleeping while the next one walks straight into the same wall.
  - **The bucket is what makes concurrent fetching possible later.** A `last_call` timestamp cannot be shared between threads — two workers read "the gap has passed" at the same instant and both fire. Taking a token is atomic under a lock, waits are *reserved* (the bucket goes into debt, so the second caller is quoted a longer wait rather than the same one), and a test with four threads on a barrier asserts they are spaced 0/1/2/3 gaps apart. Threading the fetcher's per-movie loop is still open work: that loop persists a durable ledger after every step, and it is the quota ledger — not the pacing — that has to move into the state store first.
  - 33 new tests, all on a fake clock: the pacing is arithmetic, and a test that proves it by actually sleeping is both slow and flaky.
- **`organize status` — one screen that answers "what is left to do?" without touching a single movie.** Until now the only way to find out was to run the whole toolchain and read five reports. `status` runs the auditor once for the two cheap, volatile facts (layout and subtitle presence, a stat per file) and joins the expensive verdicts — bit depth, sync, remux — from a shared cache the tools now write as they go. It prints per-step tallies, then "Nothing to do for N movie(s) — the next pass will touch M".
  - **A cached verdict is only shown while it still describes the bytes on disk.** Every verdict is stamped with the movie's `(size, mtime_ns)` — the same rule `MediaProbeCache` already used — and a mismatch is reported as `stale`, never as an answer. An unknown stamp on either side counts as stale too: guessing in the optimistic direction is how a cache starts lying about a library.
  - **A step that has never published anything is named, not silently counted.** `Remux not recorded yet` plus `(Remux not counted: no cached verdicts to count.)` under the total, so the "nothing to do" figure can never be quietly optimistic about work nobody has measured.
  - It inherits exactly one side effect from the audit it runs — a validated legacy `Title.en.srt` is renamed to the canonical `Title.eng.srt`, as `organize audit` does. No movie file is ever touched, and a test asserts it.
- **`organizekit/core/state.py` — the shared state cache (stdlib `sqlite3`, WAL, still zero runtime dependencies).** A *derived cache, never authority*: deleting `state.db` costs one slow pass, never correctness, and every tool still re-derives its verdict from live filesystem state exactly as before.
  - **Verdicts live one row per `(movie, kind)`, not one wide row per movie.** A movie's bit depth can be current while its sync verdict is stale — one wide row with one timestamp would have to report the stale one as fresh, so each verdict carries its own stamp.
  - **It fails open and fails silent.** `open_state()` never raises: `--no-state`, `ORGANIZE_NO_STATE=1`, an unwritable directory, or a `state.db` that is not a database at all all return a null store with the same API and empty answers, so no caller needs an `if cache is not None` branch and no cache problem can fail a run. `library_auditor.py`, `bitdepth.py` and `sync_subtitles.py` write through to it after their report exists, inside a `try` that logs a warning and returns.
  - `reserve_quota(provider, day, cap)` reserves a request slot atomically under `BEGIN IMMEDIATE` and refuses to go past the cap — the property that will let the subtitle fetcher run its providers concurrently without double-spending a daily quota (W4b).
  - `--state-db PATH` and `--no-state` on all three tools; the default lives beside the logs and reports (`ORGANIZE_STATE_DB` overrides), and a state file inside the media library is a config error, not a stray file the auditor later reports.
- 62 new tests (`tests/test_state.py`, `tests/test_status.py`, plus state suites in the three tools' own tests): 602 → 697 with the rate-limit suites, all offline. `tests/test_sync_subtitles.py` now points the cache at a temp database for the whole module, so the suite can never write to the developer's real state directory.

### Changed
- **The two slowest read paths now use the whole machine: `sync_subtitles.py` is 3.6× faster and `library_auditor.py` up to 7.7× on network storage.** Both walked the library one movie at a time while waiting on something that was not the CPU — an ffsubsync subprocess, a filesystem round trip. The pool that `bitdepth.py` had hand-rolled inside its `run()` is now `organizekit/core/parallel.py`, shared by all three, with the two properties the hand-rolled one lacked.
  - **`--workers 1` is an exact escape hatch.** One worker means no executor at all: the work runs inline, in input order, in the calling thread. It is the serial code path these tools had before they were parallelised, not an emulation of it.
  - **`map_ordered` returns results in *input* order however they finish.** That is what lets the auditor run in parallel and stay byte-identical: its console output is a numbered list and its report is the library's official verdict, so the worker count must not be able to change a character of either. `iter_completed` is the other trade — results the moment they exist — for the sync run, where a single job takes minutes and silence reads as a hang.
  - Measured: **`sync_subtitles.py`** 8 movies with a 0.5 s-per-sync stand-in, 4.22 s serial → 1.17 s at 4 workers, identical outcomes. **`library_auditor.py`** 600 folders with a 5 ms round trip (an HDD seek, or an SMB library), 3.13 s serial → 0.40 s at 8 workers, byte-identical report. Straight from the page cache the threads cost more than they save (0.05 s → 0.14 s) and the README says so rather than hiding it. Both benchmarks are checked in under `benchmarks/` and re-runnable: they are wall-clock measurements, which is the one thing a unit test cannot assert without becoming flaky.
  - Defaults are deliberately modest: sync uses half the CPUs capped at **4**, because each worker starts an ffmpeg that is itself multi-threaded and reads a different movie; the auditor uses half the CPUs capped at 8. Both accept `--workers N`, and a negative value is a config error rather than a surprise.
  - Safety: the sync run shares one remembered-verdict ledger between workers, so the single function that mutates it now takes a lock, and a test asserts all twelve verdicts survive a four-worker run (the lost-update case). A worker that dies takes its own movie down as a `FAILED` result, never the sweep. `KeyboardInterrupt` still propagates so each tool writes its partial report exactly as before.
  - `tests/test_parallel.py` (19 tests) pins the guarantees, including a barrier that only clears if the jobs genuinely overlap — so the test cannot degrade into passing slowly while asserting nothing.
- **Corrected in `OVERHAUL.md`: the subtitle fetcher cannot be made 5–8× faster by threading it.** The plan assumed it was bound by network round trips. It is not: every provider client sleeps to a documented rate limit (`REQUEST_GAP_SEC = 1.1`, `SCRAPE_REQUEST_GAP_SEC = 1.0`), so the run is rate-limit bound and eight threads would queue behind the same gap. The real win there is per-source token buckets so different providers run concurrently instead of one at a time, which needs the concurrency-safe quota ledger from W2; the estimate and the sequencing are updated to say so.

- **There is one description of the toolchain now, not two.** `pipeline.py` and `jellyfin_one_shot.py` each carried their own step table (`STEPS` / `STEP_PLANS`), their own list of script names, their own binary probes and their own skip-reason function, and the one-shot runner built the argv for each of the five tools by hand in six places inside a 661-line function. All of it collapses into `organizekit/core/toolchain.py`: one `Step` record per tool carrying the flag it uses for the library root, the binary it needs, the cache it reuses between passes, the log it cannot share, its per-pass timeout and the sentences the completer prints while it runs — plus one `build_step_args()` that both orchestrators call. `run_one_shot` drops from 661 to 542 lines and `pipeline.py` from 448 to 349; the three near-identical "clean tracks / inspect bit depth / sync timing" blocks become one loop over the table.
  - **This closes a real bug class rather than only shortening files.** The two copies had already drifted: one-shot answered "is mkvmerge installed?" with `shutil.which`, while `pipeline.py` and `organize.py doctor` asked the track cleaner's own resolver, which also searches the standard install locations. On a normal Windows MKVToolNix install — which does not put itself on PATH — doctor printed a green tick and the completer silently skipped every remux, pass after pass. There is now one answer to that question.
  - Verified by replay, not by inspection: a harness ran the completer against a fake library on the commit before and after, recording every subprocess argv, timeout, transcript path and console tag, plus the full run log and rendered report. The two runs are identical except that `--report` now precedes `--log` for two steps. The same check passes for the skip path (missing mkvmerge and ffmpeg), `--dry-run` and `--nice`.
  - `tests/test_toolchain.py` (19 tests) pins the merged behaviour directly: which flag names the library root for each tool (the cleaner is the odd one out with `--dir`), that only the fetcher writes to its own ledger instead of the shared run log, that caches land under `--log-dir` so a run stays self-contained, that `--dry-run`/`--nice` reach exactly the tools that understand them, and the exact wording of every skip reason. `tests/test_shared_core.py` now asserts the two orchestrators bind the *same object* (`pipeline.STEPS is jellyfin_one_shot.STEPS`), so a second table cannot be written. The suite is 576 tests, still fully offline.
  - `jellyfin_completer.sh` is finally a single `exec`: the legacy no-op `--verbose` it used to filter out is now an explicit no-op flag on the Python CLI, so the wrapper has nothing left to decide.

- **The tools no longer ship their own test suites: 2,229 lines moved to `tests/selftests/`.** `subtitle_fetcher.py` carried 1,047 lines of `run_self_tests` — including a 475-line single function — *inside the shipped file*, on top of the 1,811-line unit-test module covering the same code. Every suite moved out unchanged; each function is rebound to its tool's namespace (`tests/selftests/__init__.py`), so a body that reads or patches a module global behaves exactly as it did before the move rather than merely similarly. `tests/test_selftests.py` runs them all as part of the offline suite.
  - What `--self-test` does now is what the flag is actually for: a **field smoke test** that answers "does this copy work on this machine?" in under a second, with no repository, media library or network. The three shared guarantees (report renderer, atomic + durable write, library-root resolution) come from `organizekit/core/smoke.py`; each tool adds a few checks of its own decision logic — the auditor audits a temporary library, `bitdepth` confirms 8-bit SDR is queued and Dolby Vision protected, the standardizer verifies the filesystem supports hardlinks at all.
  - Measured coverage rose from **58% to 67%** without writing a single new assertion: self-test code inside a production file is production code the unit suite never executes. `subtitle_fetcher.py` 59% → 73%, `sync_subtitles.py` 66% → 83%, `pipeline.py` 58% → 76%, `library_auditor.py` 59% → 71%, `bitdepth.py` 48% → 61%. The CI floor moves 55 → 65.
- **The vendored helpers are gone: there is now one shared core, `organizekit/`.** Every tool used to carry its own copy of the report renderer, the atomic writer, the locking protocol, the subtitle contract and the library-root resolver — measured at **4,325 lines of literal duplication**, 2,034 of them from seven copies of one 339-line `Report` class. All of it now lives exactly once in `organizekit/core/` (`text`, `console`, `fsio`, `locking`, `subtitles`, `report`, `config`, `probecache`) and the tools import it. Production code drops from **26,458 to 21,795 lines** with no behaviour change; the suite is green at 555 tests and `ruff` is clean.
  - `tests/test_vendored_helpers.py` becomes `tests/test_shared_core.py`. It no longer *detects* drift between copies — it makes drift unrepresentable, by failing the build if any tool defines a top-level name the core already provides, and by asserting the tools bind the core objects themselves (`module.resolve_library is core.resolve_library`) rather than agreeing by coincidence.
  - The one real divergence found during extraction is fixed in the surviving implementation: `ExclusiveRunLock` had two versions, and one of them had lost the guard that writes the Windows lock byte *only when the file is empty*, appending a `0` on every retry for the lifetime of a contended wait. The per-tool contention wording is now a `busy_message` parameter instead of a reason to fork the class.
  - `load_dotenv()` used to look for `.env` beside the tool's own source file. Now that it lives in a package, it searches what the user actually ran: the entry-point script's directory, then the working directory, then the installation root. Real environment variables still win over the file, and an explicit path argument still wins over everything.
  - Packaging follows: the wheel ships `organizekit` plus the tool modules, and `pyproject.toml` single-sources the version from `organizekit.VERSION`. `python3 bitdepth.py` out of a clone still needs no install, no `PYTHONPATH` and no virtualenv, because the package sits beside the tools at the repository root.
- **`OVERHAUL.md` documents the full plan this is the first phase of** — measured duplication, the wall-clock cost of the serial fetch/sync steps, the five-walks-per-pass scan problem, and the sequenced roadmap that follows.

Ten new offline tests cover every decision branch, including the explicit `remove_commentary=False` override; the actual remux path (probe → journal → mkvmerge → verify → atomic swap) is unchanged. Seventeen more tests cover the rest of the fail-closed contract end to end: track fingerprints (flag aliases, language-tag materialization, AAC 7→8 tolerance), the verification plan/diagnostic payloads, `_verify_remux_info` accept/reject decisions (tiny output, missing audio, wrong subtitles), the transaction journal round trip, and the atomic replace/delete helpers. `mkv_track_cleaner.py` coverage rose from 39% to 41% and the overall suite from 57% to 58%; the suite is now 549 tests.
- **`jellyfin_completer.sh` is now a thin compatibility wrapper.** It forwarded a subset of flags and re-implemented `jellyfin_one_shot.py`'s arg parsing; it now execs the Python runner with every argument passed through (absorbing the legacy no-op `--verbose`). Call sites keep working; the Python CLI is the single source of flag truth again, and `--help` shows the real help.

### Fixed
- **`organize.py doctor` always reported FFmpeg/ffprobe as missing on fully-provisioned machines.** The diagnostic still imported the deleted `10bit` module (`importlib.import_module("10bit")`); every probe check fell into the except branch no matter what was on PATH, while `pipeline.py` and `jellyfin_one_shot.py` had already moved to `bitdepth.find_ffprobe()`. Doctor now asks `bitdepth` the same question, and a regression test pins the contract.
- **`organize.py doctor` ignored `ORGANIZE_LIBRARY`, `.env`, and platform-aware defaults.** It built its library/source paths from raw `MOVIE_STD_TARGET`/`MOVIE_STD_SOURCE` reads with hardcoded `E:\torrents\...` literals, so on Linux/macOS it warned about literal Windows paths and could not see the library the tools actually use. It now resolves both roots through the shared resolvers (`bitdepth.resolve_library()` / `movie_standardizer.resolve_source_root()`), with an inline fallback that keeps a copied `organize.py` self-sufficient. Tests cover env precedence and platform defaults.
- **`movie_standardizer.py`'s batch-scan source root was a literal `E:\torrents\final` on every platform.** A bare `python movie_standardizer.py` on Linux/macOS would scan a directory named `E:\torrents\final` in the working directory. New `default_source_root()` / `resolve_source_root()` give it the same platform-aware treatment as the library root (`E:\torrents\final` on Windows, `~/torrents/final` elsewhere; flag → `MOVIE_STD_SOURCE` → default), and `organize.py doctor` uses the identical rules.
- **The CLI/docs still claimed the old `E:\torrents\final` open-the-torrents-folder hint and Windows-only report default.** The pipeline's cleaner hint and the standardizer's `--report` help are now platform-neutral, and README/`.env.example` document the POSIX source-root default.

### Fixed (earlier)
- **The `organize` console script was installed broken.** `pyproject.toml` declared `organize = "organize:main"` but had no `[build-system]` table and no package, so setuptools' auto-discovery built a wheel containing metadata and a script shim pointing at nothing: `pip install -e .` reported success and `organize --help` then died with `ModuleNotFoundError: No module named 'organize'`. The README documents that install path. CI never noticed because every job invokes `python organize.py` by path. There is now a build backend, an explicit `py-modules` list, and a `packaging` CI job that builds a wheel, installs it, and runs the console script from outside the source tree.
- **`10bit.py` is now `bitdepth.py`.** A module name cannot begin with a digit, which is why the file could never be packaged and why `pipeline.py` carried a two-branch `importlib` fallback to import it. The fallback is gone. The `organize 10bit` subcommand and the `10bit` pipeline step key are unchanged.
- **Reports could be published empty after a power cut.** `atomic_write_text` had drifted into two implementations. The copy in `subtitle_fetcher.py` fsynced the staged file before renaming it; the five copies in `bitdepth.py`, `library_auditor.py`, `mkv_track_cleaner.py`, `movie_standardizer.py` and `sync_subtitles.py` did not. Without the fsync, `os.replace` can land while the bytes it points at are still only in the page cache, so the file survives a process crash but a power cut publishes an empty or partial file — and the tool that rewrites movie files had the weakest writer in the repo. All copies are now the superset implementation (fsync, `newline="\n"`, and an optional no-clobber `os.link` publish).
- **`jellyfin_one_shot.py` silently skipped steps on fully-provisioned Windows machines.** Its prerequisite check asked `shutil.which("mkvmerge")`, while `pipeline.py` and `organize.py doctor` both delegate to `mkv_track_cleaner.resolve_mkvmerge_path()`, which also searches the standard install locations. The Windows MKVToolNix installer does not add itself to `PATH`, so one-shot logged `mkvmerge: NOT FOUND` and skipped the remux while `doctor` on the same machine printed a green tick and the version string. Same bug for `ffsubsync`, which ships three interchangeable entry points (`ffsubsync`, `ffs`, `subsync`) where only the first was probed. All three surfaces now delegate to the tool that actually runs the binary.
- **A default run on Linux/macOS wrote literal `E:\torrents\...` filenames into the working directory.** The library root was a bare literal repeated across seven files and only two of nine call sites honoured `MOVIE_STD_TARGET`, so the tools that ignored it fell back to a Windows drive letter on every platform. `.gitignore` carried an `E:*` rule to sweep up the debris; that rule is now deleted because the cause is gone.

### Added
- **One shared library-root resolver, vendored identically in every tool.** Precedence: an explicit flag, then `ORGANIZE_LIBRARY`, then the legacy `MOVIE_STD_TARGET`, then a platform default (`E:\torrents\final_organized` on Windows, `~/Media/Movies` elsewhere). Logs, reports and probe caches resolve the same way, to the documented tools directory on Windows and `$XDG_STATE_HOME/organize` elsewhere.
- **`.env` files are actually read now.** `.env.example` told users to copy it to `.env`, and nothing in the codebase ever opened that file — every documented variable silently did nothing unless separately exported. Every tool now loads a `.env` beside the scripts at startup; an already-exported value always wins over the file.
- **`tests/test_vendored_helpers.py` enforces the vendoring rule that used to be honour-system.** CONTRIBUTING.md has always said "keep the other tools' copies byte-identical so they cannot drift apart"; nothing checked, and they had drifted. The suite compares all 22 shared helpers across the tools by AST (docstrings excluded, so per-tool wording is still allowed) and fails on any divergence. It also pins the two orchestration invariants that were previously documented in prose and enforced by nothing: fetcher-before-cleaner (a remux destroys the OpenSubtitles moviehash) and `pipeline.STEP_ORDER == jellyfin_one_shot.STEP_ORDER`.
- **CI now lints, gates coverage, and tests the package.** `ruff` had been configured in `pyproject.toml` for a long time but was never invoked anywhere; wiring it in surfaced 13 real issues, now fixed, with the ruleset widened to `BLE`/`SIM`/`RET`/`C4`/`PIE` and every exclusion documented with its reason. Coverage has a `--fail-under` floor measured against production code only. (Workflow changes ship as `ci-improvements.patch` — the Arena GitHub App cannot push `.github/workflows`.)

### Added
- **Subtitle fetch/sync now tries up to 10 replacement downloads per movie.** When ffsubsync rejects a candidate or cannot produce a trustworthy alignment, `sync_subtitles.py` asks `subtitle_fetcher.py` for another unused qualifying English SRT and tests it immediately. The tenth replacement is included in the retry budget; the first candidate that is already aligned or can be safely corrected is kept, while exhausting the budget restores the entry-time sidecar byte-for-byte. Version 1.2.0.
- **`subtitle_fetcher.py` now has nine sources and a hard coverage goal: a validated English SRT beside every movie.** Seven scraping fallback sources join OpenSubtitles and SubDL in a new tier-3 failover chain — **Subf2m.co → Podnapisi.NET → Addic7ed.com → SubSource.net → Subsunacs.net → YIFY Subtitles → Subs.sab.bz** — vendored into `subtitle_fetcher.py` itself (stdlib-only, no keys, no accounts), so the fetcher remains a single self-contained file. A scraped candidate is accepted only when it names the movie, matches its release year, and decodes to a valid English SRT; each source carries a per-run circuit breaker (3 hard or 3 repeated parse failures disable it for the rest of the run) and a UTC daily search cap (20 per source, `--scrape-daily-cap`) metered in the same durable ledger as the API quotas. The report now opens with a coverage scorecard and names the verdict of every source per uncovered movie; uncovered movies are re-offered to the scraping tier on every later UTC day (same-day exhaustion is never re-spent), and the process exits 1 while any movie is uncovered unless `--allow-missing` is given. A run with no API keys is valid: every movie goes straight to the scraping tier. New flags: `--scrape-daily-cap`, `--skip-source` (repeatable), `--allow-missing`.
- **`sync_subtitles.py` — subtitle-timing sync with ffsubsync, the pipeline's final content step.** Walks the whole movie library, pairs every non-junk `.srt` sidecar with its movie file (`.mkv` preferred; ffsubsync's own sibling-detection naming rule), and measures the subtitle drift against the actual audio with `ffsubsync` (`pip install ffsubsync`, needs `ffmpeg` on the PATH). Trustworthy drift is applied by atomically swapping in the corrected sidecar; sub-threshold drift (`--min-offset`, default 0.1 s) leaves the file byte-identical; untrustworthy drift — beyond the trust window (`--max-offset`, default 30 s), anti-correlated scores, ffsubsync's own `--skip-sync-on-low-quality` refusal, or any ffsubsync failure — is held for review with the original untouched. The tool writes its own detailed report and append-only log (`E:\torrents\tools\ReportsAndLogs\sync_subtitles\` by default), participates in the shared coordination lock, and exits 0 / 1 (failures) / 2 (config or missing ffsubsync) / 3 (reviews, with `--fail-on-review`) for scheduler gating. It is stdlib-only: ffsubsync is launched as a subprocess, exactly like mkvmerge and ffprobe, so the zero-pip-dependency invariant holds.
- **`pipeline.py` now has five steps: `fetcher → cleaner → 10bit → sync → auditor`.** Subtitle sync runs just before the library audit on purpose: it rewrites subtitle bytes only (never movie bytes, so the OpenSubtitles moviehash is undisturbed) but must finish first so the audit validates the finished sidecars. The step skips cleanly — with the exact fix printed — when ffsubsync or ffmpeg is not installed, matching every other step.
- **`organize.py doctor` checks `ffsubsync` and `ffmpeg`** and reports the one-line install (`pip install ffsubsync`) when they are missing; a `sync` subcommand delegates to the new tool.
- **`jellyfin_one_shot.py` version 1.0.0 — the "never stop" one-shot completer, hardened to actually finish.** The orchestrator that loops fetch → clean → 10bit → sync → audit until the auditor reports 100% canonical is now the only script in the repo that cannot quietly spin forever: an empty library (no movie folders) exits 2 with the canonical-layout reminder instead of looping on 0/0; a `--log-dir` inside the library is rejected up front (every tool refuses to write inside the media tree, and the auditor would count a log folder as a movie folder — that combination could never reach 100%); three passes in a row without a usable audit report exit 1 with the transcript paths to debug; and two passes with zero coverage improvement sleep until the next UTC midnight, when the provider daily caps reset and the scraping tier re-offers held movies, instead of hot-looping full pipeline passes. `--dry-run` now previews exactly one pass and exits 0 (a dry run writes nothing, so a second pass would be identical); `--version` and `--timeout-scale` (0 = no timeout) join the CLI. All per-tool logs, reports, probe caches, and bounded rolling full-output transcripts are pinned under `--log-dir`, so a run is self-contained on any platform. It is wired into the unified CLI as `organize.py one-shot` (aliases `oneshot`, `complete`), and `organize.py test` now runs its self-test too.

Both Subtitle Edit and pgsrip pick their own output filename, so a backend that writes `track.eng.srt` where `track.srt` was expected is still recognised instead of being counted as a failure.

- **`subtitle_fetcher.py` builds a sidecar from the movie's own embedded subtitle track before it downloads anything.** Most Jellyfin MKVs already carry the English subtitle, and that track is the best possible source: it is exact for this release (no wrong cut), it spends no provider request, and its cues come from the container's own timeline, so the sidecar is frame-accurate and needs no timing correction. For every uncovered movie the fetcher now probes the tracks with `mkvmerge -J`, keeps the complete English streams (non-English, forced/signs-only, and commentary tracks are refused, because publishing one would look like success while leaving the dialogue missing), and tries them text-first: **SRT/SSA/ASS/WebVTT** are extracted with `mkvextract` and converted to canonical SRT in-process with the standard library, and **PGS/SUP, VobSub and DVB image tracks** are handed to an external OCR backend — `sup2srt` + Tesseract, Subtitle Edit, or PgsToSrt — auto-detected in that order, with `--ocr-backend` / `--ocr-bin` / `--ocr-args` for anything else. Nothing is written unless the result clears the same gate a download clears, plus two checks that only matter for extraction: a minimum cue count (a handful of cues means the track is signs-only) and OCR-noise/English detection. If extraction cannot help, the movie falls through to the providers exactly as before, and the report says why. Extraction needs MKVToolNix; OCR needs one backend, and a machine with neither still extracts every text track and downloads the rest. Now both providers' release-identifying routes are consulted for every movie — the exact OpenSubtitles moviehash and SubDL's score-gated release-aware filename match (score ≥ 0.80) — and the qualifying release with the **most downloads** is downloaded, whichever provider it came from. When neither release route yields a pick, both providers' strict title/year routes are pooled the same way. In a cross-provider comparison a candidate must also carry the release-name policy (title, release year, Blu-ray keyword), so a high-download WEB release on one provider can never beat a qualifying release on the other. Pointing it at the shared run log would have fed another tool's output to that parser, so it keeps `subtitle_fetcher_ledger.log` beside the run log. It is durable state, like the probe caches — nothing is written to it that the run log lacks.
- **Each tool's console tail is written to the shared run log only, not printed twice.** The tail (100 lines per stream) exists so the single log tells the whole story on its own; printing it again would double every short tool's output on a console that had already streamed it live.

The `default` disposition now decides first; size breaks the tie only when the container marks nothing.
- **A movie whose bit depth is claimed twice and differently is reviewed instead of resolved.** `bits_per_raw_sample` and `pix_fmt` are independent fields and can disagree - a 10-bit pixel format behind an 8-bit raw-sample count being the common case. Both values are now reported and the movie waits in UNKNOWN BIT DEPTH, which is the group that exists for exactly this: a queue is a re-encode, and nothing is queued on a contradiction.

  `.../final/Small.1995.mkv` printed as `.../final/Small...`. Entry text now wraps at path
  separators (`common.wrap_path_text`), so the movie folder or file name always lands whole
  on its own line; the boxed header's metadata rows break the same way instead of splitting a
  directory name mid-word. A detail that shares an entry's line now really does start at its
  column instead of drifting four columns right. Tables still clip — columns have to line up.

### Added
- **SubDL is now a first-class subtitle provider.** Configure `SUBDL_API_KEY` to add SubDL's documented release-aware `/api/v2/files/search` fallback after OpenSubtitles has no safe exact-hash or title/year candidate, or run SubDL by itself when OpenSubtitles is unavailable. Automatic release picks require the response `match` to confirm the canonical movie and `match_score >= 0.80`; strict title/year lookup occurs only when the filename route yields no usable candidate, never after a low-score or ambiguous one. The v2 client uses Bearer authentication, sends only the local basename, requests the documented `format=file` opaque-ID download route, validates raw download hosts, fails closed on multi-SRT archives, rechecks the movie snapshot, and never logs provider URLs or credentials. The append-only ledger separately reserves OpenSubtitles downloads plus SubDL's documented free-tier 2,000 searches and 50 downloads per day; each SubDL search request (including a retry) and selected download is reserved before it is sent.
- **Expanded provider coverage tests** exercise SubDL v2 authentication and documented response parsing, match-record identity validation, score gating, safe URL handling, multi-file archive rejection, SubDL-only operation, release-to-title fallback ordering, and separate search/download quota reservations.
- **28 new report tests** (244 total): `tests/reporttext.py` parses the scorecard and sections back out of a rendered report, `tests/test_reports.py` builds one report per tool and asserts the shared contract, and `tests/test_common.py` covers the renderer itself (width invariants, wrapping, clipping, partial-run tallies), and `tests/test_reports.py` runs the fetcher under `PYTHONIOENCODING=ascii` to prove a hostile console cannot abort a run or corrupt the report file.
