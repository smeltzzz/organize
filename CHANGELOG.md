# Changelog

All notable changes to this project will be documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- **`mkv_track_cleaner.py`'s `process_mkv` is split into a pure `plan_cleanup()` decision plus the I/O executor.** The branch-heavy track-retention logic (English-audio selection, commentary/DVS exclusion, foreign-film-with-sidecar handling, subtitle retention, "already clean" detection) is now a dataclass-returning pure function that takes synthetic `mkvmerge -J` data, so it is testable without a remux. Ten new offline tests cover every decision branch, including the explicit `remove_commentary=False` override; the actual remux path (probe → journal → mkvmerge → verify → atomic swap) is unchanged. Seventeen more tests cover the rest of the fail-closed contract end to end: track fingerprints (flag aliases, language-tag materialization, AAC 7→8 tolerance), the verification plan/diagnostic payloads, `_verify_remux_info` accept/reject decisions (tiny output, missing audio, wrong subtitles), the transaction journal round trip, and the atomic replace/delete helpers. `mkv_track_cleaner.py` coverage rose from 39% to 41% and the overall suite from 57% to 58%; the suite is now 549 tests.
- **`jellyfin_completer.sh` is now a thin compatibility wrapper.** It forwarded a subset of flags and re-implemented `jellyfin_one_shot.py`'s arg parsing; it now execs the Python runner with every argument passed through (absorbing the legacy no-op `--verbose`). Call sites keep working; the Python CLI is the single source of flag truth again, and `--help` shows the real help.
- **The `ci-improvements.patch` file is gone.** Its workflow changes (ruff, coverage floor, packaging guard) had already been applied and committed to `.github/workflows/ci.yml`, so the standalone patch was stale; `REVIEW.md`'s note is updated to match.

### Fixed
- **`organize.py doctor` always reported FFmpeg/ffprobe as missing on fully-provisioned machines.** The diagnostic still imported the deleted `10bit` module (`importlib.import_module("10bit")`); every probe check fell into the except branch no matter what was on PATH, while `pipeline.py` and `jellyfin_one_shot.py` had already moved to `bitdepth.find_ffprobe()`. Doctor now asks `bitdepth` the same question, and a regression test pins the contract.
- **`organize.py doctor` ignored `ORGANIZE_LIBRARY`, `.env`, and platform-aware defaults.** It built its library/source paths from raw `MOVIE_STD_TARGET`/`MOVIE_STD_SOURCE` reads with hardcoded `E:\torrents\...` literals, so on Linux/macOS it warned about literal Windows paths and could not see the library the tools actually use. It now resolves both roots through the shared resolvers (`bitdepth.resolve_library()` / `movie_standardizer.resolve_source_root()`), with an inline fallback that keeps a copied `organize.py` self-sufficient. Tests cover env precedence and platform defaults.
- **`movie_standardizer.py`'s batch-scan source root was a literal `E:\torrents\final` on every platform.** A bare `python movie_standardizer.py` on Linux/macOS would scan a directory named `E:\torrents\final` in the working directory. New `default_source_root()` / `resolve_source_root()` give it the same platform-aware treatment as the library root (`E:\torrents\final` on Windows, `~/torrents/final` elsewhere; flag → `MOVIE_STD_SOURCE` → default), and `organize.py doctor` uses the identical rules.
- **The CLI/docs still claimed the old `E:\torrents\final` open-the-torrents-folder hint and Windows-only report default.** The pipeline's cleaner hint and the standardizer's `--report` help are now platform-neutral, and README/`.env.example` document the POSIX source-root default.

### Fixed (earlier)
- **The `organize` console script was installed broken.** `pyproject.toml` declared `organize = "organize:main"` but had no `[build-system]` table and no package, so setuptools' auto-discovery built a wheel containing metadata and a script shim pointing at nothing: `pip install -e .` reported success and `organize --help` then died with `ModuleNotFoundError: No module named 'organize'`. The README documents that install path. CI never noticed because every job invokes `python organize.py` by path. There is now a build backend, an explicit `py-modules` list, and a `packaging` CI job that builds a wheel, installs it, and runs the console script from outside the source tree.
- **`10bit.py` is now `bitdepth.py`.** A module name cannot begin with a digit, which is why the file could never be packaged and why `pipeline.py` carried a two-branch `importlib` fallback to import it. The fallback is gone. The `organize 10bit` subcommand and the `10bit` pipeline step key are unchanged.
- **Reports could be published empty after a power cut.** `atomic_write_text` had drifted into two implementations. The copy in `subtitle_fetcher.py` fsynced the staged file before renaming it; the five copies in `bitdepth.py`, `library_auditor.py`, `mkv_track_cleaner.py`, `movie_standardizer.py` and `sync_subtitles.py` did not. Without the fsync, `os.replace` can land while the bytes it points at are still only in the page cache, so the file survives a process crash but a power cut publishes an empty or partial file — and the tool that rewrites movie files had the weakest writer in the repo. All copies are now the superset implementation (fsync, `newline="\n"`, and an optional no-clobber `os.link` publish).
- **`jellyfin_one_shot.py` silently skipped steps on fully-provisioned Windows machines.** Its prerequisite check asked `shutil.which("mkvmerge")`, while `pipeline.py` and `organize.py doctor` both delegate to `mkv_track_cleaner.resolve_mkvmerge_path()`, which also searches the standard install locations. The Windows MKVToolNix installer does not add itself to `PATH`, so one-shot logged `mkvmerge: NOT FOUND` and skipped the remux while `doctor` on the same machine printed a green tick and the version string. Same bug for `ffsubsync`, which ships three interchangeable entry points (`ffsubsync`, `ffs`, `subsync`) where only the first was probed. All three surfaces now delegate to the tool that actually runs the binary.
- **A default run on Linux/macOS wrote literal `E:\torrents\...` filenames into the working directory.** The library root was a bare literal repeated across seven files and only two of nine call sites honoured `MOVIE_STD_TARGET`, so the tools that ignored it fell back to a Windows drive letter on every platform. `.gitignore` carried an `E:*` rule to sweep up the debris; that rule is now deleted because the cause is gone.

### Added
- **One shared library-root resolver, vendored identically in every tool.** Precedence: an explicit flag, then `ORGANIZE_LIBRARY`, then the legacy `MOVIE_STD_TARGET`, then a platform default (`E:\torrents\final_organized` on Windows, `~/Media/Movies` elsewhere). Logs, reports and probe caches resolve the same way, to the documented tools directory on Windows and `$XDG_STATE_HOME/organize` elsewhere.
- **`.env` files are actually read now.** `.env.example` told users to copy it to `.env`, and nothing in the codebase ever opened that file — every documented variable silently did nothing unless separately exported. Every tool now loads a `.env` beside the scripts at startup; an already-exported value always wins over the file.
- **`tests/test_vendored_helpers.py` enforces the vendoring rule that used to be honour-system.** CONTRIBUTING.md has always said "keep the other tools' copies byte-identical so they cannot drift apart"; nothing checked, and they had drifted. The suite compares all 22 shared helpers across the tools by AST (docstrings excluded, so per-tool wording is still allowed) and fails on any divergence. It also pins the two orchestration invariants that were previously documented in prose and enforced by nothing: fetcher-before-cleaner (a remux destroys the OpenSubtitles moviehash) and `pipeline.STEP_ORDER == jellyfin_one_shot.STEP_ORDER`.
- **CI now lints, gates coverage, and tests the package.** `ruff` had been configured in `pyproject.toml` for a long time but was never invoked anywhere; wiring it in surfaced 13 real issues, now fixed, with the ruleset widened to `BLE`/`SIM`/`RET`/`C4`/`PIE` and every exclusion documented with its reason. Coverage has a `--fail-under` floor measured against production code only. (Workflow changes ship as `ci-improvements.patch` — the Arena GitHub App cannot push `.github/workflows`.)

### Added
- **Subtitle fetch/sync now tries up to 10 replacement downloads per movie.** When ffsubsync rejects a candidate or cannot produce a trustworthy alignment, `sync_subtitles.py` asks `subtitle_fetcher.py` for another unused qualifying English SRT and tests it immediately. The tenth replacement is included in the retry budget; the first candidate that is already aligned or can be safely corrected is kept, while exhausting the budget restores the entry-time sidecar byte-for-byte. Version 1.2.0.
- **`subtitle_fetcher.py` now has nine sources and a hard coverage goal: a validated English SRT beside every movie.** Seven scraping fallback sources join OpenSubtitles and SubDL in a new tier-3 failover chain — **Subf2m.co → Podnapisi.NET → Addic7ed.com → SubSource.net → Subsunacs.net → YIFY Subtitles → Subs.sab.bz** — vendored into `subtitle_fetcher.py` itself (stdlib-only, no keys, no accounts), so the fetcher remains a single self-contained file. A scraped candidate is accepted only when it names the movie, matches its release year, and decodes to a valid English SRT; each source carries a per-run circuit breaker (3 hard or 3 repeated parse failures disable it for the rest of the run) and a UTC daily search cap (20 per source, `--scrape-daily-cap`) metered in the same durable ledger as the API quotas. The report now opens with a coverage scorecard and names the verdict of every source per uncovered movie; uncovered movies are re-offered to the scraping tier on every later UTC day (same-day exhaustion is never re-spent), and the process exits 1 while any movie is uncovered unless `--allow-missing` is given. A run with no API keys is valid: every movie goes straight to the scraping tier. New flags: `--scrape-daily-cap`, `--skip-source` (repeatable), `--allow-missing`.
- **`sync_subtitles.py` — subtitle-timing sync with ffsubsync, the pipeline's final content step.** Walks the whole movie library, pairs every non-junk `.srt` sidecar with its movie file (`.mkv` preferred; ffsubsync's own sibling-detection naming rule), and measures the subtitle drift against the actual audio with `ffsubsync` (`pip install ffsubsync`, needs `ffmpeg` on the PATH). Trustworthy drift is applied by atomically swapping in the corrected sidecar; sub-threshold drift (`--min-offset`, default 0.1 s) leaves the file byte-identical; untrustworthy drift — beyond the trust window (`--max-offset`, default 30 s), anti-correlated scores, ffsubsync's own `--skip-sync-on-low-quality` refusal, or any ffsubsync failure — is held for review with the original untouched. The tool writes its own detailed report and append-only log (`E:\torrents\tools\ReportsAndLogs\sync_subtitles\` by default), participates in the shared coordination lock, and exits 0 / 1 (failures) / 2 (config or missing ffsubsync) / 3 (reviews, with `--fail-on-review`) for scheduler gating. It is stdlib-only: ffsubsync is launched as a subprocess, exactly like mkvmerge and ffprobe, so the zero-pip-dependency invariant holds.
- **`pipeline.py` now has five steps: `fetcher → cleaner → 10bit → sync → auditor`.** Subtitle sync runs just before the library audit on purpose: it rewrites subtitle bytes only (never movie bytes, so the OpenSubtitles moviehash is undisturbed) but must finish first so the audit validates the finished sidecars. The step skips cleanly — with the exact fix printed — when ffsubsync or ffmpeg is not installed, matching every other step.
- **`organize.py doctor` checks `ffsubsync` and `ffmpeg`** and reports the one-line install (`pip install ffsubsync`) when they are missing; a `sync` subcommand delegates to the new tool.
- **`jellyfin_one_shot.py` version 1.0.0 — the "never stop" one-shot completer, hardened to actually finish.** The orchestrator that loops fetch → clean → 10bit → sync → audit until the auditor reports 100% canonical is now the only script in the repo that cannot quietly spin forever: an empty library (no movie folders) exits 2 with the canonical-layout reminder instead of looping on 0/0; a `--log-dir` inside the library is rejected up front (every tool refuses to write inside the media tree, and the auditor would count a log folder as a movie folder — that combination could never reach 100%); three passes in a row without a usable audit report exit 1 with the transcript paths to debug; and two passes with zero coverage improvement sleep until the next UTC midnight, when the provider daily caps reset and the scraping tier re-offers held movies, instead of hot-looping full pipeline passes. `--dry-run` now previews exactly one pass and exits 0 (a dry run writes nothing, so a second pass would be identical); `--version` and `--timeout-scale` (0 = no timeout) join the CLI. All per-tool logs, reports, probe caches, and bounded rolling full-output transcripts are pinned under `--log-dir`, so a run is self-contained on any platform. It is wired into the unified CLI as `organize.py one-shot` (aliases `oneshot`, `complete`), and `organize.py test` now runs its self-test too.
- **`library_auditor.py` reports a machine-readable verdict.** Every report now ends with a stable `AUDIT SUMMARY: canonical=N; total=M; pct=P%` footer line, so orchestrators parse the contract instead of the layout.
- **`tests/test_one_shot.py` — 35 new offline tests for the one-shot completer.** Coverage parsing (including a round-trip against the auditor's real rendered report), completeness rules, log-dir validation, transcript bounding, and the orchestrator's end-state behaviour (complete/partial/empty library, dry-run single pass, max-passes, persistent audit failure, lock-contention retry, UTC-rollover pacing, stagnation reset) — all with `run_tool` faked so no subprocess is launched.

- **`pgsrip` is now the first OCR backend auto-detection tries** for image-based embedded subtitle tracks (`pgsrip` → `sup2srt` → Subtitle Edit → PgsToSrt). `pip install pgsrip` (it needs MKVToolNix, Tesseract and tessdata) is enough to turn a PGS/VobSub track into the same validated SRT; `--ocr-backend pgsrip` pins it, and `organize.py doctor` names it first among the remedies. Both Subtitle Edit and pgsrip pick their own output filename, so a backend that writes `track.eng.srt` where `track.srt` was expected is still recognised instead of being counted as a failure.

- **`subtitle_fetcher.py` builds a sidecar from the movie's own embedded subtitle track before it downloads anything.** Most Jellyfin MKVs already carry the English subtitle, and that track is the best possible source: it is exact for this release (no wrong cut), it spends no provider request, and its cues come from the container's own timeline, so the sidecar is frame-accurate and needs no timing correction. For every uncovered movie the fetcher now probes the tracks with `mkvmerge -J`, keeps the complete English streams (non-English, forced/signs-only, and commentary tracks are refused, because publishing one would look like success while leaving the dialogue missing), and tries them text-first: **SRT/SSA/ASS/WebVTT** are extracted with `mkvextract` and converted to canonical SRT in-process with the standard library, and **PGS/SUP, VobSub and DVB image tracks** are handed to an external OCR backend — `sup2srt` + Tesseract, Subtitle Edit, or PgsToSrt — auto-detected in that order, with `--ocr-backend` / `--ocr-bin` / `--ocr-args` for anything else. Nothing is written unless the result clears the same gate a download clears, plus two checks that only matter for extraction: a minimum cue count (a handful of cues means the track is signs-only) and OCR-noise/English detection. If extraction cannot help, the movie falls through to the providers exactly as before, and the report says why. Extraction needs MKVToolNix; OCR needs one backend, and a machine with neither still extracts every text track and downloads the rest. New flags: `--no-extract`, `--extract-min-cues`, `--ocr-backend`, `--ocr-bin`, `--ocr-args`, `--ocr-timeout`, `--ocr-limit`. Version 2.11.0.
- **`sync_subtitles.py` never re-syncs a sidecar that was extracted from the movie.** `subtitle_fetcher.py` records every extracted sidecar outside the library (`ReportsAndLogs/subtitle_fetcher_extracted.json`, override with `SUBTITLE_EXTRACTED_LEDGER`) with its SHA-256, and the sync tool skips those files with a new `extracted` status and its own report section — running ffsubsync on them would spend an audio decode and alignment pass to prove a known zero. The record is verified, not trusted: a sidecar replaced by a download or edited by hand is measured like any other.
- **`subtitle_fetcher.py` reports what it extracted.** The scorecard gained an "Extracted from the movie" row (counted as coverage) and the report gained an "EXTRACTED FROM THE MOVIE'S OWN EMBEDDED TRACK" section, so it is always visible which movies never touched a provider.
- **`organize.py doctor` checks the extraction toolchain.** Two new checks report `mkvextract` (MKVToolNix) and the detected image-subtitle OCR backend, each with the exact install for Windows, Debian/Ubuntu and macOS when missing — matching how the doctor already reports mkvmerge, ffprobe, ffmpeg and ffsubsync.
- **`tests/test_subtitle_extract.py` — 36 offline tests for embedded extraction.** Track classification and ordering, ASS/SSA/WebVTT conversion and cue renumbering, the quality gate (short, non-Latin, OCR-noise and word-salad tracks are refused), every OCR backend's command line, the extraction record round trip, one movie extracted end to end through a faked `mkvmerge`/`mkvextract`, and the two integrations that matter: `queue_run` covers a movie from its own track without any provider, and `sync_subtitles.py` skips the resulting sidecar.

- **`jellyfin_one_shot.py` now narrates the whole run on the console, and produces one log and one report.** A long pass used to be an hour of silence followed by a good summary at the end; the console is now the primary surface. Before the first pass it prints **the plan** — each of the five steps marked `RUN` or `SKIP`, with the reason it is being skipped. Every step announces itself with what it does, why it runs in that position, and what it will skip as already done. Each tool's output is **streamed to the console as it happens**, prefixed with the step it came from (`[clean] remuxed Movie (2020).mkv`) instead of being captured and printed at the end: the child is launched with `PYTHONUNBUFFERED=1` (a pipe would otherwise block-buffer) and read by two threads, one per stream, so stdout and stderr stay interleaved and nothing waits for the process to exit. A tool that goes quiet is not a tool that has died, so every `--heartbeat` seconds (60 by default) the runner reports how long the tool has been running, how long since its last line, and how many lines it has produced — the exact question "is it even working?" gets an answer without being asked. `--quiet` turns the streaming off and keeps the banners, decisions, heartbeats and every summary.
- **One log, one report, no per-run artifact pile.** Both files have a fixed name under `--log-dir` instead of a new timestamped pair per run: `jellyfin_one_shot.log` is appended to by the orchestrator *and* by all five tools (each run starts with a banner), and `jellyfin_one_shot_report.txt` is **rewritten after every step**, so it is always the current state of the current run — readable while the run is still going, and current even if it was killed. The report carries the full detail of the current pass (each step's outcome, purpose, why it sits where it does, what it skipped, its command line, and its own report folded in verbatim) plus a compact one-line-per-pass **PASS HISTORY** table for everything before it. Per-tool report files are written to a hidden `.one_shot_stage/` folder, folded into the single report, and deleted on every exit path, so a finished run leaves the log, the report, and the durable caches the next run depends on. The pre-flight audit is recorded as its own (pass 0) section, so an "already complete" run still leaves a report explaining exactly why nothing was done. Version 1.3.0.

- **`10bit.py` reports *which* Dolby Vision a movie carries.** "Dolby Vision" on its own does not answer the practical question - whether a client with no Dolby Vision support can still play the file - and that is the difference between a movie that falls back to HDR10 and one that plays as a green and purple picture. The inspector now reads `dv_profile` and `dv_bl_signal_compatibility_id` from the configuration record ffprobe already returns and names the profile the way it is written up everywhere else: `profile 8.1 · HDR10 base`, `profile 8.4 · HLG base`, `profile 7 · HDR10 base · dual layer`, and `profile 5 · no SDR/HDR10 fallback` - each on its own line in the report and in the per-movie summary. A stream whose codec name is itself a Dolby Vision sample entry (`dvh1`, `dvhe`, `dvav`, ...) is recognised as Dolby Vision even when the file carries no configuration record to read, and a record with no profile is left undescribed rather than guessed at. Version 2.4.0.

### Changed
- **`jellyfin_one_shot.py` no longer requires `--source`: it defaults its movie library like every other tool.** It was the only script in the repo that refused to run without an explicit path, while `subtitle_fetcher.py`, `mkv_track_cleaner.py`, `10bit.py`, `sync_subtitles.py`, `library_auditor.py` and `pipeline.py` all default to `E:\torrents\final_organized`. The library root now resolves flag-first, then `MOVIE_STD_TARGET` (as `pipeline.py` already did), then the same documented default — so `py jellyfin_one_shot.py` on the documented layout finishes the library the rest of the toolchain maintains. The resolved path **and its provenance** (`--source` / `MOVIE_STD_TARGET` / the default) are written to the runtime log at the start of every run, and a path that does not exist now prints where it came from plus both ways to override it instead of a bare "does not exist". Version 1.1.0.
- **`jellyfin_one_shot.py` now decodes tool output as UTF-8 and pins its own console to UTF-8.** `run_tool` captured sibling tools with bare `text=True` (the locale encoding — cp1252 on Windows), which raises `UnicodeDecodeError` on the first box-drawing character of any report, and the script printed `✓`/`—` without pinning its own streams, which raises `UnicodeEncodeError` on exactly the success banner on a legacy Windows console. Both now follow the repo-wide contract every other tool already uses.
- **`movie_standardizer.py` self-test no longer writes into the CWD.** The self-test's config kept the Windows default report path, which on POSIX materialized as a literal `E:\...` file in the working directory; the self-test now passes `report_file=None` like it already does for the log. Its ffprobe invocation also decodes with explicit UTF-8 for consistency with the other tools.
- **CI byte-compile gate compiles the scripts that exist.** The syntax gate referenced `common.py` (removed in 3.3.0) and missed `sync_subtitles.py` and `jellyfin_one_shot.py`; it now compiles all nine runnable scripts, runs the one-shot self-test explicitly, and the stale "208 tests" comment is gone.

- **`subtitle_fetcher.py` version 2.10.0.** The tier-1/tier-2 API routing is unchanged in semantics; the new tier-3 scraping chain is entered only after both API tiers miss (and never in dry-runs, which spend no scraping requests), so existing API-key configurations behave exactly as before apart from the new report lines and the coverage-based exit code.
- **`subtitle_fetcher.py` picks the Blu-ray release that names the movie with the most downloads.** Automatic selection on both OpenSubtitles routes (exact-moviehash and the conservative title/year fallback) now requires the candidate's release name to name the movie and to carry an explicit Blu-ray keyword (`BluRay`, `Blu-ray`, `BLU RAY`, ...), and ranks the qualifying candidates by download count instead of trusted/rating/votes — those quality signals remain as tiebreakers. A download-count tie that the quality signals cannot break is still held for manual review. The score-gated SubDL fallback is unchanged.
- **`subtitle_fetcher.py` widens auto-selection to the release year and drops the quality floor.** Supersedes the bullet above: the release name must now carry the movie title, **the release year as a standalone number**, and a Blu-ray keyword, and among the qualifying candidates the one with the **most downloads** wins. The rating/votes/download minimums on the title/year route are gone, so popular-but-unvoted subtitles for big-name movies fetch automatically; trusted/rating/votes remain tiebreakers only, and an unbroken download tie is still held for manual review. Applies to both OpenSubtitles routes and SubDL's strict title/year fallback; the score-gated SubDL release route is unchanged.
- **`subtitle_fetcher.py` treats OpenSubtitles and SubDL as equal sources.** Previously OpenSubtitles always won the routing: SubDL ran only after OpenSubtitles had no safe candidate or was out of quota. Now both providers' release-identifying routes are consulted for every movie — the exact OpenSubtitles moviehash and SubDL's score-gated release-aware filename match (score ≥ 0.80) — and the qualifying release with the **most downloads** is downloaded, whichever provider it came from. When neither release route yields a pick, both providers' strict title/year routes are pooled the same way. In a cross-provider comparison a candidate must also carry the release-name policy (title, release year, Blu-ray keyword), so a high-download WEB release on one provider can never beat a qualifying release on the other. SubDL's no-weakening rule is kept (a low-score release match never falls back to its generic title route), `--no-identity-fallback` still disables SubDL (it has no hash route), per-provider daily caps are enforced independently as before, and an unbroken cross-provider tie is held for manual review.

- **`subtitle_fetcher.py` keeps its own log file under the one-shot runner.** It is the one tool for which `--log` is not a log: that append-only file *is* its durable daily-quota and retry ledger, parsed back at start-up to meter the provider caps. Pointing it at the shared run log would have fed another tool's output to that parser, so it keeps `subtitle_fetcher_ledger.log` beside the run log. It is durable state, like the probe caches — nothing is written to it that the run log lacks.
- **Each tool's console tail is written to the shared run log only, not printed twice.** The tail (100 lines per stream) exists so the single log tells the whole story on its own; printing it again would double every short tool's output on a console that had already streamed it live.

- **`10bit.py` picks the video stream the container marks as the main feature, not the largest one.** Ranking by pixel area let a full-frame bonus featurette (1920x1080) outrank a scope main feature (1920x816), so the tool read the featurette's label and could report a 10-bit movie as 8-bit and queue it for a re-encode that would only lose quality. The `default` disposition now decides first; size breaks the tie only when the container marks nothing.
- **A movie whose bit depth is claimed twice and differently is reviewed instead of resolved.** `bits_per_raw_sample` and `pix_fmt` are independent fields and can disagree - a 10-bit pixel format behind an 8-bit raw-sample count being the common case. The tool used to trust the raw-sample count and file the movie, possibly into the re-encode queue, on the strength of half a label. Both values are now reported and the movie waits in UNKNOWN BIT DEPTH, which is the group that exists for exactly this: a queue is a re-encode, and nothing is queued on a contradiction.

### Fixed
- **`mkv_track_cleaner.py` no longer refuses every remux of a movie whose only sidecar is named `.eng.sdh.srt`.** `validate_exact_external_english_srt()` accepted both covering names, but its result record always carried the canonical `<stem>.eng.srt` path even when the validated file was the SDH sibling — the field was initialized before the search and never updated. The post-remux re-check re-stats the recorded path before the atomic swap, so for those movies it checked a file that never existed and aborted with "validated external SRT changed or became invalid while remuxing" on **every** run, after spending a full remux, leaving the movie untouched forever (the standardizer itself names release-bundled SDH subtitles `.eng.sdh.srt`, so this was the normal shape, not an edge case). The log and report also printed the wrong sidecar filename. The record now names the file that was actually validated — the fetcher's covering logic has always returned the matched path — and the fix is pinned by a regression test that drives the whole live remux path with a stub `mkvmerge`, including journal round-tripping and legacy `.en.srt` promotion. Version 2.6.2. `run_ocr()` treated the "writes beside its input" lookup as always finding a path, but `find_sibling_srt()` correctly returns `None` when nothing new appeared next to the source; a backend that reported success without writing an `.srt` (e.g. an empty PGS track, a version-specific naming quirk) crashed with `AttributeError` instead of being reported as a normal OCR failure with the exit code and command tail. Version 2.11.1.
- **`jellyfin_one_shot.py` no longer risks crashing if a child process starts with no stdout/stderr pipe.** The background reader threads assumed `Popen.stdout`/`.stderr` were always present and silenced the type checker instead of checking; they now return immediately for a `None` stream instead of iterating over it. Version 1.3.1.
- **`organize.py doctor`'s OCR check now surfaces *why* `subtitle_fetcher` could not be imported or no backend was found**, instead of a generic "not found" message with the exception swallowed.
- **`jellyfin_one_shot.py` dry-run and empty-library infinite loops** (see Added above): a `--dry-run` without `--max-passes` previously looped forever because nothing it does can move the auditor's verdict, and an empty (or wrong) `--source` looped on 0/0 coverage.
- **`jellyfin_one_shot.py` hot loop when the audit keeps failing** — a broken or lock-blocked auditor left the runner on "unknown" coverage with no backoff; per-pass audit retries (5/15/45 s) plus a three-pass hard stop make the failure mode visible and bounded.
- **`sync_subtitles.py` remembers what it already measured, so a re-run costs nothing.** Measuring a movie means a full ffsubsync run — an audio decode and an alignment pass — and the answer cannot change while the two files are unchanged. A sidecar that measured "in sync", or was corrected and swapped in, is now recorded outside the library (`ReportsAndLogs/sync_subtitles/sync_state.json`, override with `--sync-ledger` or `SUBTITLE_SYNC_LEDGER`) with the subtitle's SHA-256 and the movie's size and mtime. The record is treated as evidence, never as a decision: it is honoured only while **both** the sidecar bytes and the movie bytes still match it, so a re-downloaded, re-extracted, hand-edited or replaced subtitle, or a remuxed or replaced movie, sends the sidecar straight back through ffsubsync. Held-for-review and failed syncs are never recorded — those still need another attempt. The report gained a "Remembered in sync" scorecard row and a "REMEMBERED IN SYNC (NOT RE-MEASURED)" section, the log gained the same count, a dry run reads the memory to show what a live run would skip and never writes to it, and the ledger is rejected inside the library exactly like `--log` and `--report`. Deleting the file re-measures everything. `jellyfin_one_shot.py` pins it under `--log-dir` (`--sync-ledger <log-dir>/sync_state.json`) like every other artifact of a run. Version 1.1.0.
- **`jellyfin_one_shot.py` audits before it works, so a finished library is left alone.** The orchestrator used to run all five tools and only then ask the auditor whether the library was complete — so re-running a library that finished yesterday cost a full sweep for nothing. A live run now audits first (the auditor is filesystem-only: it reads folder layout and the sidecar, never the container) and, when the verdict is already 100%, exits 0 with a banner naming what the verdict does and does not cover. `--force-pass` restores the old behaviour for a real sweep — which is the right thing when movies still carry extra audio tracks or embedded subtitles, because the auditor's contract deliberately does not inspect the MKV's own tracks. A pre-flight audit that is blocked or broken is not a verdict: the run falls through to the normal pass loop with its retries and bad-audit accounting intact, and an empty library is still caught (exit 2) before any sweep. `--dry-run` is unchanged and always previews exactly one pass. Version 1.2.0.
- **`mkv_track_cleaner.py` no longer re-scans every movie on the run right after it cleaned them.** The probe cache stores `mkvmerge -J` output keyed on `(size, mtime)`, but the entry was written from the *pre-remux* stat, while a remux deliberately restores the source mtime and changes the size. That entry could therefore never match the file it described, so the next run re-ran a full container scan of every movie the previous run had just cleaned — the whole cost of a "nothing left to do" maintenance pass, for a library that had not changed. The cache is now re-keyed onto the file that actually exists, using the verification probe of the finished output (the same bytes `mkvmerge -J` would return). Measured on a simulated 10-movie library: the pass after the remux went from 10 container scans to 0, and it stays at 0 on later passes. Version 2.6.1.

## [3.3.0] - 2026-08-30

## [3.2.0]

### Changed
- **Every report now shares one layout.** A new renderer in `common.py` (`Report`, `report_banner`, `print_text`) draws all six reports — `subtitle_fetcher.py`, `library_auditor.py`, `mkv_track_cleaner.py`, `movie_standardizer.py`, `10bit.py` and the `pipeline.py` summary — with the same boxed header, the same right-aligned scorecard, and the same titled sections. Each report leads with the counts, then a one-line "Start here:", then the groups ordered by how cheap the fix is, then the full inventory. Nothing overflows the page and no line carries trailing whitespace.
- **`subtitle_fetcher.py`'s report answers the two questions you actually ask.** Movies are no longer dumped into one flat list tagged with a status word: every result now carries a machine-readable reason, so the report splits cleanly into **MOVIES THAT NEED A SUBTITLE** (grouped by the fix — unusable sidecar, misnamed sidecar, layout defect, held for review, no provider match, deferred by quota, error) and **MOVIES THAT ALREADY HAVE AN EXTERNAL `.eng.srt`** (every covered movie listed with its sidecar file name). Movies the UTC cap cut off before they were scanned are now *named* in the report instead of only counted.
- **`library_auditor.py` leads with defects.** "Folders that need attention" now comes first, grouped by fix, with the full folder-by-folder inventory and the file-type table moved behind it.
- **`10bit.py` leads with the queue.** The HandBrake queue and the two REVIEW groups come first; native-HDR and already-high-bit-depth movies are listed last, as confirmation that nothing should be touched.
- **`mkv_track_cleaner.py` leads with what needs a decision** — errors, movies remuxed without a validated `.eng.srt` (moviehash now invalidated), hardlink-deferred movies and layout skips — before the per-movie remux detail.
- **`movie_standardizer.py` leads with `ITEMS LEFT IN SOURCE`**, the only section where inaction silently leaves files in the torrent folder forever.
- **Tool output no longer clutters the torrents root on Windows**: logs, reports, and probe-cache JSON now default to `E:\torrents\tools\ReportsAndLogs\<tool>\` (e.g. `E:\torrents\tools\ReportsAndLogs\mkv_track_cleaner\mkv_track_cleaner.log`) instead of five folders at the root of `E:\torrents`. Existing hooks scheduled with direct tool paths pick this up automatically; anything using explicit `--log`/`--report`/`--cache` paths is unaffected.
- **Foreign films with a validated `.eng.srt` are now cleaned** by `mkv_track_cleaner.py`: the best non-commentary audio of any language is kept, commentary/DVS is dropped, and every embedded subtitle is stripped so the external SRT is the sole subtitle option. Foreign films *without* a validated sidecar remain untouched.
- **Canonical external subtitle suffix is now `.eng.srt`** (ISO 639-2/B) instead of `.en.srt`.
  `subtitle_fetcher.py` writes `.eng.srt`, `mkv_track_cleaner.py` requires it before stripping embeds,
  `library_auditor.py` and `movie_standardizer.py` treat it as the sole canonical sidecar name.
  A validated legacy `.en.srt` is automatically renamed to `.eng.srt` on the next fetcher, cleaner, or auditor run.

### Fixed
- **`movie_standardizer.py --help` reported a stale default report path.** The `--report` help string claimed an old default of `E:\torrents\movie_standardizer\movie_standardizer_report.txt`, but the actual default (and the report that is written) is `E:\torrents\tools\ReportsAndLogs\movie_standardizer\movie_standardizer_report.txt`. The help now matches the real constant, consistent with every other tool's `ReportsAndLogs` default.
- **`mkv_track_cleaner.py --version` printed the old script name.** It hardcoded `track_cleaner.py {VERSION}`; every other tool derives its name from the invoked path (`%(prog)s`). It now prints `mkv_track_cleaner.py {VERSION}`.
- **Placeholder-free `f`-strings and an unused `except` binding were removed** (`organize.py`, `library_auditor.py`) — caught by the project's `ruff` rules.
- **Reports no longer depend on the console's encoding.** Every tool now pins its own stdout/stderr to UTF-8 with `errors="replace"` on *every* platform (`common.enable_utf8_stdio`; previously this ran on Windows only), the `log()` helpers print through the encoding-safe path, and every caller that captures a child process — `organize.py` and the test suite — decodes it as UTF-8 instead of with the locale encoding. Before this, a boxed report was a `UnicodeDecodeError` waiting to happen on Windows (cp1252) and a `UnicodeEncodeError` on a runner with no locale set. The report *file* is written UTF-8 either way, so a limited console degrades to `?` instead of losing data or aborting a run.
- **Report entries wrap instead of being cut off.** `Report.entry()` used to ellipsize an
  entry that overflowed the 96-column page, which silently destroyed exactly what the line
  was there to name: on macOS the standardizer's source paths run ~90 columns, so
  `.../final/Small.1995.mkv` printed as `.../final/Small...`. Entry text now wraps at path
  separators (`common.wrap_path_text`), so the movie folder or file name always lands whole
  on its own line; the boxed header's metadata rows break the same way instead of splitting a
  directory name mid-word. A detail that shares an entry's line now really does start at its
  column instead of drifting four columns right. Tables still clip — columns have to line up.

### Added
- **SubDL is now a first-class subtitle provider.** Configure `SUBDL_API_KEY` to add SubDL's documented release-aware `/api/v2/files/search` fallback after OpenSubtitles has no safe exact-hash or title/year candidate, or run SubDL by itself when OpenSubtitles is unavailable. Automatic release picks require the response `match` to confirm the canonical movie and `match_score >= 0.80`; strict title/year lookup occurs only when the filename route yields no usable candidate, never after a low-score or ambiguous one. The v2 client uses Bearer authentication, sends only the local basename, requests the documented `format=file` opaque-ID download route, validates raw download hosts, fails closed on multi-SRT archives, rechecks the movie snapshot, and never logs provider URLs or credentials. The append-only ledger separately reserves OpenSubtitles downloads plus SubDL's documented free-tier 2,000 searches and 50 downloads per day; each SubDL search request (including a retry) and selected download is reserved before it is sent.
- **Expanded provider coverage tests** exercise SubDL v2 authentication and documented response parsing, match-record identity validation, score gating, safe URL handling, multi-file archive rejection, SubDL-only operation, release-to-title fallback ordering, and separate search/download quota reservations.
- **28 new report tests** (244 total): `tests/reporttext.py` parses the scorecard and sections back out of a rendered report, `tests/test_reports.py` builds one report per tool and asserts the shared contract, and `tests/test_common.py` covers the renderer itself (width invariants, wrapping, clipping, partial-run tallies), and `tests/test_reports.py` runs the fetcher under `PYTHONIOENCODING=ascii` to prove a hostile console cannot abort a run or corrupt the report file.
